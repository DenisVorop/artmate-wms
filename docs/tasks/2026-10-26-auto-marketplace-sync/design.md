# Решение

Серверный планировщик стартует только из main после запуска API, не из createApp/OpenAPI/тестов. Цикл при запуске и на границах0/30мин. Подключения последовательно, один атомарно захваченный запуск на площадку/получасовой слот, общий SQL lock только на claim/publish, сеть снаружи. lastAttemptAt/runId/version сохраняют дедупликацию после рестарта и между процессами. Отключение/замена ключа во время сети отменяет публикацию старого ответа.

Фоновый вход внутренний, без HTTP endpoint и выдуманной сессии. Ручная команда сохраняет свежую manager/CSRF/replay проверку. Один общий fetch/publish механизм сохраняет budgets, complete-only и null semantics. Остановка сервера отменяет свой сетевой запрос. Автосборка задач не появляется. Web опрашивает готовую серверную проекцию раз30сек как раньше; простой текст сообщает об обновлениикаждые30мин.
