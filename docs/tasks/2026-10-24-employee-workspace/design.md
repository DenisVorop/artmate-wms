# Решения

- Пользователь: сотрудник с телефоном и впоследствии HID-сканером. Задача — выполнить физическую операцию, видя только следующий шаг.
- `/work` — отдельное рабочее место без WorkspaceShell/sidebar/таблиц/метрик. Управленческие маршруты сохраняются; рабочие прямые ссылки сотрудника ведут к соответствующему компактному сценарию.
- Одна основная операция (`rule/one-primary-action`); лучшее значение по умолчанию вместо лишнего выбора (`rule/smallest-intervention`). Явное взятие задания, никакого claim из эффекта. Назначенные задания приоритетнее свободных; фактический исполнитель из сессии.
- Физический перенос имеет приоритет над другой работой. Продолжение незавершённого собственного задания сохраняется. Размещение с накопителя добровольное, без автоматического claim после сборки.
- Сканер вводит код и Enter. Поле видно, имеет имя и фокус; ручной ввод раскрывается отдельно. Каждый скан получает отдельную серверную команду. Одинаковые товарные штрихкоды не дедуплицируются.
- Последовательная очередь сканов относится к одному контексту: сотрудник/операция/короб. Ошибка останавливает очередь и сохраняет непринятый код; исправление повторяет его с защитой транспорта от двойного учёта. При смене контекста неотправленные сканы не применяются к следующему коробу. Количество меняется только после ответа API.
- Скан QR повторно необходим как физическое подтверждение; ожидаемый код никогда не подставляется вместо фактического скана. Число/тип товара и партии определяет API.
- У каждого сценария: loading, no tasks, busy, stale, failed scan, offline/expired session; ошибки краткие и восстановимые, ввод сохраняется (`rule/cover-reachable-states`, `rule/preserve-user-input`). Реальная работа без сети не заявляется.
- Приёмка/перемещения/инвентаризация доступны из «Другие работы», история/карта/выработка остаются вспомогательными ссылками. В рабочем процессе нет планирования, назначения, создания отгрузок или корректировок руководителя.
- FSD: widgets/employee-workspace компонует новые features/employee-assembly, employee-handling, employee-workday и compact export существующего stocktakes. Shared EmployeeScan — только ввод/очередь, без бизнес-логики; DTO из Orval.
