# Доступ с телефона в складской сети

WMS работает на включённом компьютере склада. Телефон подключается к той же локальной сети. Интернет-публикация и туннели не создаются. Внешний API и база остаются на loopback.

## Подготовка на компьютере

После обычной сборки выполните:

```sh
yarn phone:setup
yarn start
```

`phone:setup` использует установленный OpenSSL, находит IPv4-адреса RFC1918 на активных внешних сетевых интерфейсах, исключая известные VPN и виртуальные адаптеры, и создаёт `.data/phone-access/`. Закрытые ключи имеют права `0600`, каталог — `0700`; всё исключено из Git. Сертификат сервера действует 365 дней, содержит IP SAN, назначение TLS server и подписан отдельной локальной CA. Системное доверие на компьютере команда не изменяет.

Консоль покажет:

- `https://<IP>:3443/work` — рабочий экран сотрудника;
- `http://<IP>:3442` — только инструкция подключения и публичный сертификат CA;
- SHA-256 отпечаток CA для проверки на телефоне.

Сохраните локальную CA и её ключ в защищённой копии: замена CA потребует повторной настройки телефонов. Не передавайте сотрудникам `.key` файлы.

## Первое подключение телефона

1. Подключите телефон к складскому Wi-Fi. Если компьютер использует Ethernet, Wi-Fi должен иметь доступ к этой же сети; гостевая изолированная сеть не подойдёт.
2. Откройте адрес инструкции `http://<IP>:3442` из консоли. На этой странице нет входа, складских данных и команд API.
3. Скачайте `Artmate-WMS-CA.cer`, сверьте его SHA-256 отпечаток с консолью на доверенном компьютере и установите локальную CA. Корневая CA — доверенный издатель сертификатов, поэтому ключ CA должен оставаться только у владельца WMS.
4. На iPhone установите скачанный профиль в настройках. Затем включите полное доверие: **Настройки → Основные → Об этом устройстве → Доверие сертификатам → Artmate WMS Local CA**. Ручная установка профиля сама по себе не включает TLS-доверие. [Инструкция Apple](https://support.apple.com/en-us/102390).
5. На Android найдите в настройках установку **сертификата CA** (в разделе безопасности, шифрования и учётных данных) и выберите скачанный файл. Названия зависят от производителя и версии ОС; может понадобиться PIN экрана. Нужен CA для веб-сервера, а не личный сертификат с ключом и не настройка WPA-Enterprise. [Справка Google об установке сертификатов и разделе учётных данных](https://support.google.com/pixelphone/answer/2844832?hl=en).
6. Откройте `https://<IP>:3443/work`. Браузер должен считать соединение доверенным; если есть ошибка сертификата, проверьте CA, адрес и дату телефона до входа. Войдите под аккаунтом сотрудника. При желании добавьте страницу на главный экран через меню браузера.

Проверка на конкретном телефоне и пальчиковом сканере остаётся аппаратным этапом. Работа без сети не реализована.

## Повторный запуск и смена адреса

При наличии готовой конфигурации обычный `yarn start` запускает HTTPS gateway вместе с WMS. Адреса и срок сертификата проверяются перед стартом; при изменении IP обновляется только серверный сертификат, CA сохраняется. Сотрудники открывают новый адрес, CA повторно устанавливать не надо. Лучше закрепить адрес компьютера в DHCP роутера.

Локальный `http://127.0.0.1:3080` сохраняется. Если LAN gateway не смог запуститься (нет сети, порты заняты, сертификат недоступен), localhost продолжает работать, ошибка выводится в консоль. Порты `3442/3443` должны быть разрешены в локальном брандмауэре для Node и складской сети; никакого проброса портов на роутере не требуется. Сам компьютер должен оставаться включённым и не уходить в сон во время смены.

Чтобы отключить доступ с телефонов, остановите WMS, переименуйте `.data/phone-access/config.json`, затем запустите WMS заново. CA сохраняйте, если планируется повторное подключение.

## Техническая граница

- Gateway исключает известные VPN и виртуальные интерфейсы (utun/tun/tap, awdl/llw, WireGuard/Tailscale, Docker/bridge и VM-адаптеры) и слушает только найденные приватные IPv4 физических сетей, не `0.0.0.0`, не публичный адрес и не IPv6.
- Принимаются только приватные IPv4 клиентов, точный Host `IP:3443` и обычный относительный request target. API и Web выбираются по `/api` или `/api/`; upstream фиксирован на loopback 4080/3080, не берётся из пользовательского ввода.
- HTTP 3442 обслуживает только `/`, `/phone-setup` и `/ca.cer`. Никакой раздачи каталога или приватных ключей нет.
- Gateway удаляет клиентские `Forwarded`/`X-Forwarded-*` и hop-by-hop заголовки. Исходный `Origin` и CSRF сохраняются; API получает точный allowlist HTTPS origins из стартового процесса, штатные проверки сессий/ролей остаются.
- Каждый `Set-Cookie` на HTTPS-границе получает `Secure`, в том числе очистка сессии. Localhost HTTP не меняет режим cookie. Маркеров доверия и `trust proxy` в API не добавлено.
- Все LAN listeners принадлежат процессу `scripts/start.mjs`, вместе останавливаются при SIGTERM/SIGINT; их параметры отражены в `.data/app-processes.json`.

Проверка скриптов: `yarn test:phone` (OpenSSL и временные loopback-listeners, без доступа к реальной БД и без установки CA в системное доверие).
