# Требования к Artmate WMS

## 1. Исходная ситуация

Поставки приезжают с производства на паллетах. Сейчас размещение выбирается вручную, очередность использования партий выдерживается непоследовательно. Готовые короба собираются в запас, стоят на паллетах и затем используются для комплектации отгрузок. Паллеты размещаются на стеллажах и на полу. В месте хранения доступ к готовым коробам может быть с одной стороны. По уточнению владельца паллету готовой продукции всегда можно спустить и получить доступ со всех четырёх сторон. Новые короба поверх старых всё равно могут создавать лишние перемещения или нарушение FIFO.

Владелец хочет видеть остатки и текущие действия сотрудников, считать собранные раскраски и короба, выдавать задания через телефон со сканером на пальце.

## 2. Подтверждённые требования

| ID | Требование |
|---|---|
| R-01 | Входящая паллета и паллета хранения готовой продукции содержат один SKU; общая накопительная паллета сборки допускает короба разных тематик |
| R-02 | У каждой тематики есть товарный штрихкод |
| R-03 | Входящие паллеты заранее не промаркированы; WMS должна создавать уникальные QR-коды при приёмке |
| R-04 | Нужен визуальный конструктор склада: вид сверху, выбор секций, настройка ярусов и ячеек |
| R-05 | Нужны адреса и печатные QR-коды мест хранения для наклейки на стеллажи и напольные места |
| R-06 | Размещение должно учитывать габариты, высоту и вместимость места |
| R-07 | Вместимость отличается для раскрасок до упаковки и для готовых коробов |
| R-08 | Поставка содержит номенклатуру, количество, паллеты; система автоматически предлагает размещение |
| R-09 | Сотрудник авторизуется на телефоне, начинает смену и получает задание |
| R-10 | Задание на сборку задаёт тематику, число коробов и число раскрасок в коробе |
| R-11 | Сотрудник сканирует товар и код короба; система учитывает результат сборки |
| R-12 | Готовые короба сначала попадают в зону сборки, затем перемещаются на места хранения |
| R-13 | Задание на размещение готовых коробов первоначально задумано как добровольно выбираемое второстепенное |
| R-14 | Нужно учитывать FIFO при использовании раскрасок и отборе готовых коробов |
| R-15 | Нужен корректный учёт короба, в котором остаток старой партии дополнен новой |
| R-16 | Нужна статистика по сотрудникам, текущим заданиям, раскраскам и коробам |
| R-17 | Короба собираются в запас; отгрузки комплектуются из готового запаса |
| R-18 | В перспективе данные маркетплейсов должны помогать прогнозировать сборку и запас |
| R-19 | Создание заданий в первой версии должно быть предельно простым и заменяемым |
| R-20 | Паллету готовой продукции можно спустить и обеспечить доступ со всех четырёх сторон; отбор должен учитывать этот сценарий |
| R-21 | Реализация — отдельный монорепозиторий artmate-wms на Next.js и NestJS; решение владельца от 23 октября 2026 года |
| R-22 | NestJS генерирует Swagger/OpenAPI, веб через Orval получает типы и API-клиент; источник описания API — backend |
| R-23 | FIFO партий определяется датой поступления на склад; дата производства не определяет старшинство |
| R-24 | Разные партии одной тематики можно хранить на одной готовой паллете при нехватке старой партии; паллета хранения по-прежнему содержит один SKU |
| R-25 | Очередность коробов внутри одной партии важна как предпочтение; абсолютная строгость не требуется |
| R-26 | Количество отгрузки задаётся независимо от собранного количества; неотгруженные короба сохраняются в запасе |
| R-27 | В зоне сборки одна общая накопительная паллета для всех тематик; отдельные короба размещаются по тематическим паллетам хранения через добровольные второстепенные задания |

Числа из обсуждения: паллета с 1000 раскрасок; короб с 20 раскрасками; место под паллету с 18 готовыми коробами. Это контрольные примеры для настройки и проверки, а не жёсткие значения для всей номенклатуры.

## 3. Термины

| Термин | Значение |
|---|---|
| Тематика / SKU | Один вид товара со своим товарным штрихкодом |
| Производственная партия | Происхождение товара с производства, если оно известно |
| Учётная партия WMS | Отдельная прослеживаемая партия; может создаваться при приёмке, если производства не дают номера партии |
| Поставка | Документ поступления, содержащий одну или несколько позиций и паллет |
| Входящая паллета | Физическая паллета с неупакованными в отгрузочные короба раскрасками одного SKU |
| Готовый короб | Уникальная маркированная упаковка с конкретным содержимым и связью с исходными партиями |
| Паллета хранения готовой продукции | Физическая паллета с готовыми коробами только одного SKU |
| Общая паллета сборки | Накопительный поддон с готовыми коробами разных тематик до второстепенного размещения |
| Адрес / ячейка | Конечное место, которое можно отсканировать для подтверждения размещения |
| Зона | Область склада: приёмка, хранение, сборка, готовая сборка, отгрузка, карантин |
| Резерв товара | Количество или конкретные короба, выделенные под задание |
| Резерв места | Занятая будущим размещением вместимость; отдельно от резерва товара |
| НЗП | Раскраски, переданные в сборку, включая открытые незавершённые короба |
| FIFO | Правило выбора более старого допустимого запаса с сохранением причины отклонения |

В интерфейсе сотрудника предпочтительно «Раскраски до сборки», а не «сырьё»: речь о готовом товаре до комплектации коробов.

## 4. Границы первой версии

### Входит

Один склад; несколько сотрудников; одна организация. При этом warehouse_id используется в данных, чтобы расширение не требовало переделывать идентификаторы.

1. Справочник тематик, товарных штрихкодов и вариантов упаковки.
2. Карта склада и конструктор с конечными адресами.
3. Габариты, схемы укладки и разные профили вместимости для входящих и готовых паллет.
4. Печатные листы QR для мест, паллет и коробов.
5. Поставки, фактическая приёмка, партии и предложения по размещению.
6. Размещение с подтверждением сканированием.
7. Смены, ручные задания на сборку, сканирование каждой раскраски, учёт НЗП.
8. Смешанные короба с количественным составом по партиям.
9. Перемещение готовых коробов на паллеты и перемещение паллет между адресами.
10. Простое ручное создание отгрузки и отбор готовых коробов по FIFO.
11. Инвентаризация по месту/паллете, повреждения, возврат из сборки, исправления с журналом.
12. Остатки, текущая работа, статистика и аудит.
13. Резервирование, защита от повторных команд и конкурентных изменений.
14. Резервное копирование, восстановление и базовый мониторинг.
15. Спуск готовой паллеты в зону отбора, работа с четырёх сторон и возврат остатка на хранение.

### Позже

Интеграции маркетплейсов, автоматический прогноз, автоматическое пополнение по минимальному запасу, оптимизация маршрутов, 3D-карта, загрузка плана из CAD, универсальный конструктор упаковок, полноценная работа без сети, внешние бухгалтерские документы, расчёт зарплаты и сложная многоскладская логистика.

Простая отгрузка входит в первую версию: без неё нельзя проверить FIFO готового запаса и достоверно списывать отгруженные короба. Задание сборки может пополнить несколько будущих отгрузок, а одна отгрузка — использовать короба из нескольких завершённых заданий. В отгрузку резервируется только запрошенный объём.

Частичный отбор паллеты является штатным сценарием: из 18 коробов можно забрать 5, вернуть паллету с 13 на хранение и позднее продолжить отбор. Это не означает вскрытие отдельного короба или требование отправить весь результат сборки.

## 5. Роли и границы действий

| Роль | Основные действия |
|---|---|
| Владелец / администратор | Пользователи, настройки, карта, отчёты, права, утверждение спорных корректировок |
| Руководитель склада | Приёмка, задания, приоритеты, отгрузки, перераспределение, причины отклонения FIFO |
| Приёмщик | Подтверждение количества, маркировка паллет, размещение |
| Сборщик | Смена, принятие задания, сборка, пауза, завершение, доступные перемещения |
| Сотрудник отгрузки | Отбор назначенных коробов, консолидация, подтверждение отгрузки |

Одному человеку можно назначить несколько ролей. Роль проверяется на сервере. Общие учётные записи не подходят для персональной статистики.

## 6. Неизменяемые правила учёта

1. Входящая паллета и паллета хранения не содержат больше одного SKU. Общая паллета накопления в зоне сборки — явное исключение: в ней хранятся отдельные промаркированные короба разных тематик.
2. Короб в MVP содержит один SKU, но может содержать несколько партий этого SKU.
3. Каждый физический короб и каждая паллета имеют уникальный постоянный идентификатор.
4. Код SKU, код партии, код паллеты и код места выполняют разные роли.
5. Остаток меняется только подтверждённой операцией с автором, временем и основанием.
6. План или рекомендация размещения сами по себе не меняют физическое местонахождение.
7. Свободный остаток не уходит ниже нуля; резерв не превышает допустимый остаток.
8. Перемещение не создаёт и не списывает товар.
9. Упаковка переводит товар из НЗП в готовый короб с сохранением количества по партиям.
10. Отгрузка списывает товар один раз; отбор в зону отгрузки сам по себе не считается выбытием.
11. Редактирование карты не перемещает физический товар и не освобождает занятые места.
12. Операции, влияющие на остатки, нельзя исправлять удалением истории; используются обратные или корректирующие операции.
13. Повтор одной сетевой команды не считается новой складской операцией.
14. Изменение упаковки не меняет задним числом содержимое уже закрытых коробов.
15. Активные резервы товара и мест учитываются во всех проверках вместимости и доступности.

## 7. Конструктор и рабочая карта

### Структура

Склад → зоны → объекты на плане → секции → ярусы → адреса.

Напольное место имеет адрес непосредственно. Стеллаж занимает площадь на плане; его секции и ярусы раскрываются по нажатию в боковой панели или отдельном виде спереди.

### Редактор

- Масштаб в метрах; прямоугольники помещения, зон, стеллажей и напольных мест.
- Перемещение, изменение размеров, поворот кратно 90°, привязка к сетке.
- Проходы и препятствия, чтобы нельзя было размещать паллету в проходе.
- Сторона доступа к секции и напольному месту.
- Копирование одинаковых секций и пакетное создание адресов.
- Понятная адресация: зона, ряд, секция, ярус, место.
- Черновик, проверка ошибок, предпросмотр изменений и публикация версии.
- Запрет пересечений физических объектов; вложение зоны и стеллажа допустимо.
- Запрет удаления занятого адреса, адреса с активным резервом или незавершённым заданием.
- Запрет уменьшения вместимости ниже занятой или зарезервированной.
- Архивирование освобождённых адресов; история операций продолжает ссылаться на прежний адрес.

### Рабочий режим

- Цвет занятости, блокировки, ожидания перемещения и внимания.
- Легенда и текстовые статусы: информация доступна без различения цветов.
- Фильтры по тематике, партии, зоне, свободной вместимости и заданиям.
- Нажатие на место: паллета, короба, партии, количество, резервы, история и допустимые действия.
- Нажатие на секцию: все ярусы с фактической загрузкой и доступной высотой.
- Поиск по адресу, штрихкоду SKU, QR паллеты и короба.
- Время последнего обновления и признак потери связи.
- Перетаскивание объектов доступно в редакторе; перемещение товара оформляется отдельным действием со сканированием.

### QR адресов

Постоянный ID адреса; человекочитаемое обозначение; текст зоны и яруса. Смена подписи не должна менять внутреннюю ссылку, но создаёт задачу заменить физическую этикетку. До подтверждения замены показывается предупреждение о старой подписи. Удалённый адрес не переиспользуется для другого физического места.

Печать по складу, зоне, секции или выбранным адресам; предпросмотр и PDF на обычном принтере. Формат наклеек уточняется по реальному принтеру. Прямая печать на конкретную модель термопринтера не требуется до проверки оборудования.

## 8. Вместимость

Хранить габариты в целых миллиметрах, массу в граммах. В интерфейсе показывать привычные сантиметры, метры и килограммы.

Для адреса: полезная ширина, глубина, высота, число паллетомест, ограничения массы и разрешённые формы хранения. Для MVP конечный адрес предпочтительно соответствует одному паллетоместу; несколько паллет оформляются отдельными адресами.

Для входящей паллеты: фактические габариты, высота вместе с поддоном и фактическое количество. Количество раскрасок не определяет высоту автоматически, пока нет проверенного профиля укладки.

Для готовой продукции: габариты короба, поддона, число коробов в слое, число слоёв, максимальная высота, разрешённая схема укладки. Если высота короба h, поддона hp и допустимая высота H с учётом настроенного зазора, предел по высоте равен floor((H − hp) / h). Отрицательный результат даёт нулевую вместимость.

Итоговый предел равен минимуму проверенных ограничений схемы укладки, высоты и массы, если масса известна. Вместимость слоя не выводится из отношения площадей без проверки ориентации коробов. Неизвестная масса не считается нулевой и не позволяет заявлять проверку грузоподъёмности; для мест с обязательной проверкой массы размещение блокируется до заполнения данных.

На первом этапе готовые схемы укладки вводятся вручную и подтверждаются физическим измерением. Универсальный алгоритм упаковки в объём не нужен.

Пример 1000 → 50 коробов → 18 + 18 + 14 показывает потребность в трёх паллетах готовой продукции. Это не означает обязательное резервирование сразу трёх постоянных ячеек: часть результата может стоять в разрешённой зоне готовой сборки. Но общая разрешённая вместимость должна покрывать конкретный выпускаемый объём.

## 9. Рабочие экраны

| Экран | Минимальное содержание |
|---|---|
| Обзор | Остатки до сборки, НЗП, готовое, карантин, отгрузка, сотрудники, проблемы |
| Карта | План, фильтры, загрузка ярусов, карточки адресов |
| Номенклатура | Тематики, штрихкоды, варианты упаковки, размеры |
| Поставки | Ожидаемое и фактическое, паллеты, партии, QR, размещение |
| Ручное задание | Тематика, число коробов, вариант упаковки, приоритет |
| Моя смена | Начать/закончить, текущее задание, результаты, состояние связи |
| Сборка | Источник, открытый короб, прогресс N из M, сканирование, ошибки, пауза |
| Перемещения | Доступные задания, источник, цель, последовательность сканирования |
| Отгрузки | Потребность по тематикам, резерв коробов, отбор, консолидация, отправка |
| Остатки | SKU → партии → паллеты/короба → адреса; свободно/в резерве |
| Инвентаризация | Адрес, пересчёт, расхождения, утверждение |
| Сотрудники | Текущая активность, смены, выпуск, перемещения, ошибки |
| История | Операции, сканирования, отклонения, авторы и основания |
| Настройки | Пользователи, роли, оборудование, печать, профили вместимости |

Мобильные экраны: крупное текущее действие, видимый счётчик, сканирование без открытия клавиатуры, различимые подтверждения и ошибки. Для ошибок недостаточно только звука: нужен текст и визуальный сигнал.

## 10. Показатели и ограничения интерпретации

Считать завершённые принятые короба, раскраски в них, открытое НЗП, время активной сборки, перемещения, паузы и ошибки. Скорость сравнивать с учётом тематики и упаковки. Время в открытом задании не считать доказательством непрерывной работы.

«Сотрудник занят сборкой» означает наличие активного задания и последнее действие. При отсутствии событий показывать время последнего действия, не назначать человеку автоматически статус «бездействует».

Плановые метрики пилота: уменьшение перекладываний, соблюдение FIFO без скрытых исключений, совпадение остатков, время на короб, ошибки сканирования и заполнение зоны готовой сборки. Целевые значения задаются после замера текущего процесса.
