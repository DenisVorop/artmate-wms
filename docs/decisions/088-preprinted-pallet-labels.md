# ADR088: запас этикеток входящих паллет

Дата: 2026-11-05. Статус: принято.

На складе нет интернета на компьютере с принтером, но телефоны работают онлайн.
Все носители должны печататься заранее: постоянные зоны/адреса, товарные штрихкоды,
свободные короба и свободные паллетные QR. Полный офлайн-учёт не требуется.

## Сценарий

Руководитель создаёт комплект 1–1000 универсальных паллетных кодов и печатает либо
сохраняет в PDF свободные страницы до100этикеток. Пустая этикетка содержит большой QR,
номер в комплекте и код комплекта, без выдуманного товара, даты или количества.
Номер/комплект помогают человеку различать этикетки; сканируется полный QR.
Для свободных этикеток доступны75×120 и100×70мм; постоянные таблички
сохраняют свои отдельные форматы.

Приёмка создаётся обычным способом с реальными тематиками/количеством/датой.
На телефоне сотрудник входит по QR зоны приёмки, видит тематику и количество,
наклеивает свободную этикетку на текущую паллету и сканирует. Первый скан атомарно
привязывает код к этой паллете. Далее нужен QR физического адреса: только размещение
пополняет баланс. При отсутствии свободного адреса этикетку можно привязать,
но шаг размещения остаётся недоступным до появления подходящего места.

## Архитектура

Schema19 добавляет pallet_label_batches/preprinted_pallet_labels/pallet_label_commands.
Выпуск создаёт только идентификаторы. Источник контракта — DTO Nest/Swagger → Orval.
FSD: entity читает комплекты, feature управляет выпуском/печатью; телефонный сценарий
остаётся в employee-handling. Общие стили печати с запасом коробов — shared/ui.
Registry не включён в WorkspaceDto. Отдельная команда bindReceiptPalletLabel
исполняется в существующем SQL lock с actor/working/foreign claim и namespace guards.

ID паллеты, приёмки и партии сохраняются. pallet.code становится выданным PLT-PRE;
прежний QR по pallet.id продолжает работать. Новый QR по точному текущему PLT-PRE-code
принимается при размещении, сборке и перемещении. Один код связан только с одной
паллетой и не освобождается после её расхода/вывоза. Повтор того же кода для своей
паллеты безопасен; чужая/неизвестная этикетка и попытка заменить уже связанную отвергаются.
Приёмочный bind не является приходом, сборкой или выработкой и не меняет количество.

## Продуктовые решения и состояния

- rule/smallest-intervention, rule/no-redundant-entry: прежние два шага «паллета → адрес»,
  без дополнительной формы выбора, ручного ввода SKU или повторного количества.
- rule/name-object-scope-consequence: крупная инструкция говорит наклеить свободную
  этикетку именно на показанную тематику; успешный первый скан означает сохранённую связь.
- rule/cover-reachable-states, rule/error-states-recovery: пустой запас предлагает комплект;
  неполные QR блокируют печать; занятая этикетка оставляет первый шаг; нет места — ожидание
  адреса. Потеря сети сохраняет скан для повтора, успех не выдумывается.
- rule/preserve-user-input: поздний ответ прежней сессии/размонтированного шага не переводит
  новый экран вперёд. Смена code после bind не пересоздаёт компонент и не теряет первый скан.
- rule/keyboard-complete-flow: привычный scanner+Enter/поле/камера идут через общий gateway,
  правильность/ошибка озвучиваются только по принятому результату операции.

Ограничения: телефоны должны быть онлайн. Первичный ввод существующего товара пока
использует отдельный прежний сценарий печати; не выдавать его за уже поддержанную
привязку свободных паллетных этикеток. Этикетки готовых коробов выпускаются своим
независимым комплектом. Повторная печать создаёт копии того же кода, не новые этикетки.
