# ADR 004 — Интерактивный план склада

Статус: принято для первого рабочего среза.

## Решение

План склада — настоящий SVG, встроенный в Next.js. Сверху показаны стеллажи, напольные места и рабочие зоны. Пользователь выбирает адрес мышью, касанием или клавиатурой (Tab, Enter/Space). В режиме конструктора Pointer Events дают перетаскивание с привязкой к сетке 0,5 м. Координаты вычисляются через обратную матрицу SVG, поэтому масштабирование не нарушает точность перемещения.

Размеры плана и координаты отображаются в метрах. Полезная высота задаётся отдельно в миллиметрах. Вместимость готовой паллеты задаётся количеством коробов. Это независимые параметры: 1000 отдельных раскрасок и 18 готовых коробов по 20 раскрасок занимают разный объём.

Мутация выполняется только после завершения перетаскивания. До ответа сервера новое положение — локальный визуальный preview, а серверный snapshot остаётся источником истины. При отказе preview сбрасывается и показана ошибка. Новое пользовательское действие получает requestId; сетевой повтор того же запроса должен сохранять исходный requestId.

Создание/редактирование адресов использует React Hook Form + Zod. Локальная проверка помогает заполнить форму, окончательное решение принимает NestJS. Форма закрывается только после успешного сохранения. Типы и API-функции генерируются Orval из OpenAPI NestJS, собственных дублирующих API DTO у feature нет.

Новая форма предлагает свободную позицию рисунка вместо наложения на первый стеллаж. Это помощь конструктору, а не алгоритм складского размещения. Фоновое обновление snapshot не сбрасывает незавершённый ввод: reset формы происходит только при открытии или смене идентификатора адреса.

QR генерирует сервер по постоянному идентификатору адреса. UI получает LabelDto, показывает SVG как изображение и печатает отдельную светлую этикетку с читаемым кодом. Изменение подписи адреса не меняет идентичность адреса.

## Границы FSD

- `features/warehouse-layout/ui` — SVG, карточка адреса, формы и этикетка, локальный CSS module.
- `features/warehouse-layout/lib` — состояние взаимодействия с картой, schema/defaults/mappers формы.
- `features/warehouse-layout/model` — операции адресов и получение этикетки.
- Данные приходят через публичный `entities/workspace`, transport/cache bridge находится в `shared/api/use-warehouse-commands`.
- Внешний код импортирует только `WarehouseLayoutFeature` из публичного `index.ts`.

## Честные ограничения первого среза

`levels` — описание секции, а не самостоятельные адреса ярусов. Занятость показана суммарно по адресу; интерфейс явно предупреждает об этом. Следующий этап должен выделить независимые ячейки/ярусы и адресные этикетки, прежде чем использовать их для реального многоярусного размещения.

Геометрия карты не проверяет ширину/глубину входящей паллеты: в текущем API паллета имеет высоту, но ещё не ширину и глубину. Приёмка проверяет полезную высоту. Полная геометрическая проверка потребует добавить габариты поддона и груза. Автоматический поиск схем укладки и 3D не входят в этот срез.

Занятость берётся из фактических паллет и сохранённых коробов. Нет фиктивных процентов заполнения, независимых остатков ярусов, локального authoritative storage или успешных уведомлений до подтверждения API.

## Визуальный подход

Тёмный угольный фон, тонкие прозрачные панели и один изумрудный акцент. Типы мест различаются формой/штриховкой и подписью, а не только цветом. Карточка выбранного адреса остаётся читаемой отдельно от карты. Reduced motion отключает переходы; на небольших экранах карта прокручивается, карточка переносится вниз.
