# ADR072: сохранённый план при фоновом обновлении

Дата: 2026-10-27. Статус: принято.

Начало импорта, его сбой или новый день не должны обнулять экран. Полные marketplace snapshots и история уже сохранялись, но строгие проверки актуальности скрывали рассчитанные количества. Forecast worker также временно не имеет результата для нового входного ключа.

В forecast_results отдельный документ marketplace_plan_display хранит последний доступный sanitized план и даты источников. Он привязан к аккаунтам/версиям подключений, mappings, SKU/упаковке, настройкам, политикам и версиям моделей/расчёта. Transient import state, день и revision истории не инвалидируют отображение. Смена магазина или конфигурации не допускает прежний результат. Отображение читает документ после manager auth; никакой внешний запрос или обучение не выполняется в GET.

Overview содержит текущий строгий plan, nullable previousPlan и planStatus. При фоновом пересчёте, ошибке или устаревшем источнике предыдущий совместимый план остаётся доступен с исходными числами и датами. Он не выдаётся за сегодняшний прогноз: UI явно сообщает дату расчёта и день покрытия продаж. Формы пересчёта складского остатка и товара в пути используют текущую строгую строку, а не замороженные количества. Неизвестные отдельные товары остаются неизвестными.

При установке версии без опубликованного плана разрешено один раз восстановить предварительную проекцию из последних полных snapshots, только если lastSuccessVersion===version у всех включённых подключений. Режим восстановления допускает давность источника и отсутствующий последний день, но не подменяет unknown нулём, не меняет исходные snapshots и не ослабляет mapping/coverage/stock/inbound guards. Это явно подписанный расчёт по сохранённым данным, не точное восстановление исторического расчёта. Если данных недостаточно, предыдущий план не выдумывается.

Все canCreate/backlogCanCreate в previousPlan выключены. Команда создания всегда заново вызывает обычный строгий marketplacePlan, проверяет права/proposalHash и физические ограничения. Кэш отображения не является основанием складского движения. Склад, остатки, FIFO, ключи, история, смены и реальные задания не меняются публикацией этой проекции.


## Готовый прогноз и строки, требующие проверки — 2026-11-05

Инцидент: актуальный forecast cache опубликован, обе интеграции успешно обновлены,
но все строки требуют проверки: срок агрегатного подсчёта старше семи дней либо
остаток приблизительный. После изменения настроек старый display cache несовместим.
Прежнее требование хотя бы одной dataComplete строки скрывало весь строгий план
под бесконечным «Пересчитываем план под текущие настройки…».

При cacheCurrent===true, подтверждённых версиях активных магазинов и syncStatus=success
у всех активных подключений строгая проекция доступна для просмотра даже без единой
полной строки. planStatus=current означает готовность отображаемого расчёта;
допуск к созданию задают прежние row.dataComplete/canCreate/backlogCanCreate.
Сообщение объясняет необходимость проверить данные, список показывает конкретные
причины и существующую форму подтверждения остатков. Нулевой каталог открывает
штатное пустое состояние. Никакие остатки, даты подсчёта и факты не подтверждаются
автоматически, числовые неизвестные не заменяются нулём.

Такие review-строки не перезаписывают последний полный сохранённый display cache.
При реально ещё не опубликованном прогнозе, смене аккаунта или running/failed/partial
синхронизации действуют прежние guards и правила предыдущего расчёта. Исправление
не меняет DTO, клиент, модель прогнозирования, импорты и автоматическое создание работ.
Проверены просроченный точный/приблизительный остатки после смены настроек,
неизменность countedAt/units и предыдущего cache, а также пустой каталог.


## Сохранение строк проверки при следующем обновлении — 2026-11-05

Повторное воспроизведение: после публикации нового forecast один импорт Ozon
завершился failed. Условие syncStatus=success вновь скрывало все review-строки;
при следующем worker key gap для них также не было совместимого display cache.

В forecast_results отдельно сохраняется marketplace_plan_review_display с тем же
compatibilityKey и исходными датами. Публикуется только при cacheCurrent===true
и подтверждённых версиях магазинов; последняя полная проекция не перезаписывается.
Готовая review-проекция доступна также при running/failed/partial: состояние
импорта отражается строгими row guards, а не скрытием списка товаров. Приоритет
имеют совместимый полный display и допустимый bootstrap из сохранённых источников.
При worker gap review используется как nonExecutable previousPlan с явной датой.
Смена аккаунта/настроек/политик инвалидирует её по прежнему compatibilityKey.
Повторный GET не меняет время сохранённого расчёта без изменения содержимого.
Счётчики остатков, дата их подтверждения, схема БД и модель не меняются.
