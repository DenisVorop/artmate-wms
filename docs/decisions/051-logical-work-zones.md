# ADR 051 — Рабочие зоны поверх существующих адресов

Принято: 24.10.2026.

Рабочая зона — логическое объединение существующих адресов с отдельным стабильным QR. Её назначение: приёмка, сборка, размещение готовых коробов или отгрузка. Зона не является помещением, паллетоместом или складским контейнером и не добавляет вместимость. Геометрия, физический stock, IDs адресов, паллет, коробов и FIFO сохраняются.

## Конструктор

В режиме конструктора появился блок «Рабочие зоны»: активные зоны, создание/редактирование, ссылка на печать QR, архивирование в корзину и восстановление. Одна зона может объединять несколько допустимых адресов; один адрес может участвовать в разных назначениях. Для сборки действует серверный общий canonical assembly address; UI предлагает только его. Для приёмки допустимы receiving-адреса, для размещения — assembly-источники, для отгрузки — picking/shipping. Сервер повторно проверяет актуальность состава и ограничения работы.

Форма на RHF/Zod сохраняет введённые значения при polling и отказе API. Она сбрасывается только при открытии или выборе другой зоны. При создании пустые name/code делегируют атомарное назначение серверу; при редактировании существующий код и название нельзя стереть; код не надо изобретать вручную. Неподходящие ранее выбранные адреса показаны явно и требуют снятия отметки или изменения назначения. Ответ API является единственным подтверждением сохранения; modal закрывается после успеха.

Выбор зоны подсвечивает адреса отдельным пунктирным контуром; обычное выделение места/яруса и управление картой сохраняются. У зоны нет второй геометрии, drag/resize или скрытых физических адресов. Поэтому перенос и изменение размеров помещений продолжают работать с теми же объектами и адресными ID; связи зоны сохраняются автоматически. Удаление зоны — архивирование с восстановлением, без удаления адресов или товаров.

В карточке выбранного адреса доступны именные QR-ссылки его активных рабочих зон. Печать использует общий маршрут `/labels/work-zone/:id`; она не выполняет складскую операцию. Адресный QR и QR рабочей зоны имеют разные назначения и остаются отдельными.

## Архитектура и проверка

Всё конструкторское представление находится в `features/warehouse-layout`; форма, мапперы и eligibility — в lib, мутации — через model/use-location-actions и shared useWarehouseCommands, DTO — из Swagger/Orval. Собственные копии API-контрактов не вводятся. Public API feature не меняется.

Чистые тесты проверяют ограничения назначений, canonical assembly priority, физически пустую паллету, архивы/блокировки и отличие логической принадлежности от физического резерва, обязательный непустой состав, отсутствие дубликатов и отсутствие геометрических/складских полей в DTO зоны. Существующие map/geometry тесты проверяют неизменность прежнего поведения.
