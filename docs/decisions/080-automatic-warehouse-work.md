# ADR 080 · Автоматическая очередь складских работ

Дата: 2026-10-27. Статус: принято по запросу пользователя.

## Решение

Отдельный WorkAutomationService работает поверх опубликованного плана и фактического склада. План и прогноз остаются чтением; задания создаёт отдельный серверный планировщик. Scheduler запускается только main, каждые 15 секунд, без параллельных циклов; остановка отменяет цикл и ожидает завершения до закрытия БД. Конструкторы и Swagger экспорт не запускают работу.

Schema18 добавляет automation_settings, automation_tasks (происхождение и архив снятых заданий), automation_commands. Складские факты, auth, старые ответы и журнал не переписываются миграцией. Управление доступно руководителю с повторной проверкой сессии/CSRF под SQL lock. Автоматика по умолчанию включена; выключение прекращает создание/пересчёт, уже существующие задачи остаются.

Автоматическая сборка свободная, без исполнителя: один неначатый заказ на SKU, срочный пакет до 10 коробов либо один короб впрок. Учитываются ручная очередь, WIP, сырьё по FIFO и будущая физическая вместимость хранения. Неразмеченные/приблизительные остатки блокируют создание. При изменении потребности пересчитываются только неначатые свободные автоматические задания, сохраняя идентичность; снятие сохраняет исходную задачу и причину в automation_tasks. Назначенные и начатые задачи сохраняются.

Разбор общей паллеты использует существующие задания размещения отдельных коробов, создаваемые последним сканом. Не дублировать их фиктивной задачей на всю паллету. При ≥80% вместимости очередь повышает приоритет ожидающего размещения над ожидающей сборкой. Физический перенос и уже начатая работа остаются первыми. Можно сканировать любой готовый короб, затем адрес, без поиска назначенного короба.

Полная паллета блокирует начало нового короба, учитывая слоты уже подтверждённых коробов других сотрудников. Начатый короб может завершиться. Выбор следующей сборки пропускает недоступные задачи и не откатывает завершение предыдущей. Другую рабочую зону сотрудник выбирает её QR; автоматического переноса сотрудника между зонами нет.

## Границы

Планировщик не создаёт приход, выработку, перемещение товара без сканов или поставку маркетплейсу. Неизвестная вместимость объясняется в UI. Количества, печатные QR и существующие процессы сканирования сохраняют прежние серверные проверки.

## Уточнение о поддонах

Пользователь подтвердил: все поддоны — европаллеты 1200×800 мм. Фактические профили всех 23 SKU и все размещённые паллеты уже имеют эти размеры, изменения остатков не нужны. Вместимость зависит от коробов, высоты места и ограничений массы; автоматика не предлагает другой формат поддона. Универсальная геометрическая проверка сохранена для совместимости прежних данных.
