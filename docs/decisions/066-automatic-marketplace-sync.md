# ADR066 — Обновление WB/Ozon каждые30мин

Принято 26 октября2026: пользователь поручил обновлять продажи, остатки и поставки автоматически без кнопок.

## Решение

Внутренний Nest provider MarketplaceScheduler использует выровненный Node timer для расписания :00/:30. Он запускается только в main после listen, выполняет один startup catch-up и очередные получасовые слоты. Нет внешнего HTTP cron endpoint, OS cron, задач Codex или новой зависимости. Создание приложения для Swagger/тестов таймер не запускает. WB и Ozon обрабатываются последовательно, ошибка одной площадки не отменяет другую. После сна используется текущий слот без накопления старых.

syncMarketplaceAutomatically — внутренний вход, запрещающий HTTP requestAuth context. Полномочие ограничено уже подключёнными и включёнными площадками; нет выдуманной сессии и обхода ручных прав. Фоновый процесс не создаёт tasks, mappings, warehouse stock, auth или commands. Ручной вход сохраняет validate/manager/CSRF/replay и свежую проверку после сети.

Атомарный claim под существующим SQL advisory transaction lock записывает runId, lastAttemptAt и syncMode. Запуск пропускается, если попытка уже была в текущем слоте или свежая работа ещё идёт. Пять минут — граница просроченной работы; восстановление возможно в более позднем слоте. Поэтому два процесса и restart не умножают запросы. Сеть, расшифровка и ожидания снаружи SQL lock; ключ только в памяти. Общие fetch/publish сохраняют4мин/180попыток/80МБ, endpoint allowlist и provider pacing.

Публикация снова проверяет enabled/version/runId. Только полный ответ нужной площадки заменяет snapshot. Ошибка/partial сохраняют прежний снимок и отметку ошибки. lastSuccessVersion привязывает успешный снимок к версии подключения: во время автоматического running его можно использовать при прежней полноте и свежести; новый ключ, старые данные или manual running не получают послабления. Неизвестные количества остаются неизвестными.

Shutdown отменяет свой fetch, откатывает отменённую публикацию и освобождает только свой claim. main ожидает scheduler.stop перед app.close, чтобы SQL pool оставался доступен до завершения записи статуса. Некооперативный provider не блокирует остановку благодаря abort race; поздний ответ не публикуется.

Web уже читает проекцию каждые30секунд. Основной экран сообщает «Обновляется автоматически каждые30минут»; ручное обновление перенесено в настройки. Никакого эффекта, который инициирует импорт, нет. Расчёт задач по-прежнему создаётся только явным действием пользователя.

## Проверка

Тесты используют fake clock и временные БД: старт/границы/сон/stop, последовательность и отсутствие overlap, durable dedup и manual/auto конкуренция, disabled/missing connections, stale lease, reconnect, ошибки/partial/wrong-provider, shutdown и rollback, неизменность склада/auth/mappings/commands, отсутствие секретов в сообщениях. Живая проверка — существующие подключения и запуск API без нажатия кнопок.

## Догоняющий слот

Если длинный цикл пересекает следующую получасовую границу, планировщик запоминает её и после завершения выполняет один цикл для последнего актуального слота. Старые пропущенные интервалы не ставятся в очередь. Весь drain использует общий promise и AbortController: shutdown дожидается очистки и не запускает оставшихся провайдеров. Это исключает ожидание следующего получаса архивом, который уступает текущему импорту.
