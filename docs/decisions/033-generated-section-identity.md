# ADR 033 — Автоматические код и название секции

Дата: 24.10.2026. Статус: принято.

При открытии формы новой секции клиент предлагает первый свободный номер: `R-01` / «Секция 1». Из всех секций и адресов, включая архивные, собираются занятые коды и названия с нормализацией регистра и пробелов. Кандидат исключается, если занят его код, название или один из двадцати будущих адресов ярусов. Проверяются также пересечения кодов секций и адресов для однозначности чтения.

Первый ярус получает `R-01-01` / «Секция 1 · Ярус 1». Дополнительные ярусы используют прежние значения профиля и нумерацию. Поля остаются редактируемыми. Кнопка «Сгенерировать заново» явно подставляет новые значения секции и её новых ярусов. Отмена не резервирует номер и не создаёт объекты.

Генерация запускается при открытии формы создания, а не на каждом обновлении Workspace. Поэтому пользовательский ввод и ошибки не сбрасываются фоновым опросом. Форма редактирования сохраняет прежний код, название и адреса; автоматического переименования старых секций нет.

Это предложение клиента, без резервирования номера. Существующий API проверяет уникальность при сохранении внутри транзакции. При одновременном создании другим клиентом конфликт сохраняет ввод; повторная генерация учитывает обновлённый Workspace. Контракт Nest/Swagger → Orval и схема базы не меняются.

Подбор расположен в feature/lib, данные всех секций и адресов передаёт WarehouseLayout, форма использует RHF/Zod. Применён product-design `rule/smallest-intervention`: обязательный ручной ввод заменён готовыми значениями. Проверки коллизий, пропусков, архивных кодов и перехода 99 → 100 описаны в тестах; браузерные результаты — в VERIFICATION.
