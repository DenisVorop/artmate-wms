# ADR 007. Подтверждённые перемещения и подготовка отгрузки

Дата: 23 октября 2026. Статус: реализовано в локальном прототипе этапа 2.

## Сценарий перемещения

Планирование, физический забор и фактическое размещение — отдельные действия. Создание задания резервирует цель, но не меняет адрес товара. При заборе сотрудник вводит или сканирует код паллеты и исходного адреса; при размещении — паллеты и целевого адреса. Эти поля изначально пустые: нажатие на видимый код не выполняет подтверждение. Без оборудования разрешён ручной ввод тех же значений. Сервер проверяет их точное совпадение.

Список показывает активные, завершённые и отменённые задания. После выбора задания справа находится его выполнение, статус и текущий остаток. Отмена доступна только до забора. Для паллеты в пути завершение размещения остаётся единственным штатным следующим шагом.

Форма планирования поддерживает перемещение, спуск для отбора и возврат остатка. Исполнитель выбирается из сотрудников на смене. Спуск предлагает только адреса picking с доступом с четырёх сторон. Удержание источника по умолчанию включено; при наличии удержания возврат разрешён только на удерживаемый адрес. Без удержания паллету из зоны отбора или отгрузки можно вернуть на свободный адрес хранения; обычное перемещение позволяет освободить зону отбора в пользу зоны отгрузки с сохранением удержания. Автоподстановка адреса в плане не является подтверждением сканирования. Видимый остаток отражает текущее количество, включая частичный отбор.

Нулевая паллета продолжает занимать физический адрес. Действие «Поддон вывезен» открывает диалог, объясняет освобождение адреса и удерживаемого возврата и требует скан/ручной ввод паллеты и исходного адреса. Только успешная команда API снимает физическую занятость.

## Отгрузка

Черновик сохраняет резерв конкретных коробов независимо от перемещения. Кнопка отправки заблокирована, пока все выбранные короба не размещены в picking/shipping и их паллеты не находятся на адресе. Список показывает код паллеты, текущий адрес, число выбранных коробов и удерживаемое место возврата.

«Подготовить к отгрузке» открывает форму выбора свободного picking-адреса с четырёхсторонним доступом и сотрудника на смене. Создаётся lower с keepSourceReserved=true. Дальнейшее выполнение происходит в общем разделе перемещений, без автоматических подтверждений. После подтверждения размещения отправка становится доступна. После частичной отгрузки предлагается перейти к возврату остатка; после полного отбора — подтвердить вывоз пустого поддона.

## Архитектура

`features/movements`: схемы Zod, преобразования форм, UI-state и предварительные подсказки в lib; команды API в model; интерфейс в ui; публичный MovementsFeature через index.ts. `features/shipments` использует собственные lib/model/ui без импорта внутренностей соседнего feature. Контракты генерирует Orval из NestJS OpenAPI. Shared API перечитывает актуальный snapshot после команды, включая идемпотентный повтор.

Проверка доступности в select — предварительная подсказка для оператора. Сервер остаётся источником истины для габаритов, удержаний, резервов, статусов и конкурентных команд. Ошибки API показываются рядом с действием. Операции не записывают остатки в браузер и не подменяют сканирование фиктивными подтверждениями.
