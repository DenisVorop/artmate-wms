# ADR065 — Понятный план сборки

Принято 26 октября 2026 по требованию пользователя: технические подробности внутри сервиса, интерфейс показывает простые действия.

## Решение

Сервер возвращает для каждой строки advice со state, message и action. Причина формируется в исходных проверках подключения, полноты истории, сопоставлений, остатков и поставок. Клиент не разбирает текст blockers/warnings. Арифметика, FIFO, dataComplete, canCreate и proposalHash не изменены. Диагностика остаётся доступна сервису и документации. Контракт проходит Swagger/Orval и обязательный runtime guard.

| Состояние | Действие пользователя |
| --- | --- |
| Можно собирать | Создать задание |
| Не хватает сырья | Открыть приёмку |
| Требуется обновление/связь/остаток | Проверить данные маркетплейсов |
| Неизвестен товар в пути | Уточнить поставки |
| Запаса достаточно | Сборка не нужна |

Основной план содержит сводку и три списка: нужно собрать, нужна проверка, все товары. В сводку количества входят только полные рекомендации; неопределённость не скрывается за нулём. Необходимые действия и дефицит видны сразу, остальные количества — через Подробнее. Редактирование запаса свёрнуто; ручное уточнение пути сохраняет валидацию, значение и предупреждение о замене автоматического количества до обновления.

Маркетплейсы показывают статус, дату данных и обновление; настройки подключения, товары и документы свёрнуты. Ошибки обновления явные, но без технических текстов. Подключение после сохранения ключа не объявляется проверенным; последняя успешная дата не подменяется датой попытки. API-ключ требуется только внутри явной настройки доступа.

Подходы product-design: rule/smallest-intervention, rule/inline-before-modal, rule/cover-reachable-states, rule/error-states-recovery, rule/one-primary-action. Нет изменения данных при просмотре, переключении списков и раскрытии деталей.
