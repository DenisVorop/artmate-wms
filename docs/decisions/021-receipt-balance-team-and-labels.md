# ADR 021 — Баланс после размещения, сотрудники и этикетки приёмки

Статус: принято для этапа документов приёмки.

## Баланс и ожидающие паллеты

Глобальные показатели остатков берутся из серверного `WorkspaceDto.balance`. UI не пересчитывает общий баланс по всему массиву паллет: документ приёмки может уже существовать, а его паллеты ещё не размещены. Такие `awaiting_placement` не относятся к учтённому товару.

Inventory показывает `totalUnits` как «На балансе, шт.», отдельно `rawUnits`, `workInProgressUnits` и `boxedUnits`. Dashboard использует тот же total, а также серверные составляющие до сборки/в работе и количество раскрасок в готовых коробах. Ожидающие объёмы и паллеты показываются в приёмке, а не прибавляются к этим показателям.

Для таблицы по SKU используется локальная проекция из generated DTO: raw учитывается только у `stored` и `in_transit`, WIP — по `task.scannedUnits`, готовый товар — по `stored` коробам. Уже учтённый товар не исчезает из баланса во время складского перемещения. Резерв не прибавляется к total, поскольку остаётся частью исходного товара.

В таблице паллет ожидающие размещения исключены. Вывезенные пустые поддоны могут оставаться историческими строками с явным статусом; они не дают остаток. Физическая занятость на dashboard по-прежнему считается только по `stored` паллетам и фактическим коробам с адресом, включая физически стоящие пустые паллеты.

## Минимальная команда на пустой базе

Team получил форму добавления сотрудника: имя обязательно, должность необязательна. React Hook Form + Zod проверяют ввод, mapper обрезает пробелы и не отправляет пустую должность. `createEmployee` проходит через общий typed API bridge и получает новый snapshot. Уникальность имени, ID, инициалы и начальные нулевые показатели задаёт сервер.

Сотрудник создаётся вне смены. После успешного добавления его карточка выделяется и объясняет следующий шаг — «Начать смену». Существующая команда начала смены переводит его в `working`, после чего приёмка может выбрать исполнителя. На пустой базе показан отдельный путь добавления первого сотрудника.

Ошибки не закрывают форму и не стирают имя. Polling workspace не сбрасывает текущий ввод. Pending блокирует повторную запись и закрытие формы. Добавление сотрудника и начало смены остаются отдельными действиями; это создание демонстрационного исполнителя, не готовая система аутентификации или прав доступа.

## Этикетки документа

Новая feature `receipt-labels` читает typed `getReceiptLabels(id)` из Orval. Тонкий маршрут `/receiving/[id]/labels` передаёт ID в `_pages/receipt-labels-page`, который компонует публичный API feature. Здесь нет прямого обращения к базе или копирования API-контрактов.

Страница показывает уникальный код паллеты, название тематики, исходное количество строки документа и фактическую дату поступления. Количество не вычисляется из текущего остатка паллеты: частичная сборка или последующее перемещение не переписывают приёмочную этикетку. Даты отображаются в Europe/Moscow.

QR приходит с сервера как реальный SVG, отображается через data-URL в `img`. SVG не вставляется в DOM через innerHTML и не исполняет код страницы. Изображения имеют состояния готовности и ошибки; печать доступна после загрузки всех QR, сбойный QR можно перезагрузить отдельно. Ошибка получения документа показывает retry и путь к приёмкам.

Кнопка вызывает `window.print()` по явному действию пользователя. Print CSS задаёт `@page size:100mm 70mm`, нулевые поля, фиксированную белую этикетку того же размера и разрыв страницы после каждой паллеты. Экранный заголовок и действия скрываются. Внешний `_pages` wrapper не имеет inline padding, который мог бы сместить печатные страницы.

Повторная печать читает те же серверные pallet IDs/payload; она не создаёт новые QR и не размещает паллеты. Формат макета 100×70 мм показан в интерфейсе. Браузерная проверка страницы и CSS не означает проверки физического принтера: параметры бумаги и драйвера подтверждаются на оборудовании.

## FSD и проверка

- `inventory/lib/inventory-balance` — чистая проекция по SKU и фильтры учтённых паллет; глобальный balance остаётся серверным.
- `team/lib` — schema/defaults/mapper и локальное состояние диалога; `team/model` — команды; `team/ui` — форма и карточки.
- `receipt-labels/model` — typed read hook, `lib` — состояние загрузки QR и печати, `ui` — экран и print CSS.
- Связь с общей инфраструктурой идёт только вниз по слоям через public entity API, generated API и shared UI. Новая feature не импортирует соседнюю receiving feature.

Изолированные тесты проверяют исключение ожидающей приёмки из SKU-остатка и паллетного представления, сохранение учтённого in-transit товара, правильную сумму raw+WIP+stored boxes и отсутствие pending в резерве. Тест формы сотрудника проверяет пустое имя и корректное отсутствие optional должности. Сквозной сценарий приёмка→сотрудник→смена→размещение→баланс и браузерная страница этикеток проверяются root на отдельной базе.
