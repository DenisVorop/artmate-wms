# ADR-038 — экран журнала и подтверждение корректировок

Статус: принято, 24 октября 2026.

## Решение

Журнал читается отдельным entity hook через сгенерированный Orval API. `stock-ledger` feature отвечает за RHF/Zod-фильтры, страницы и раскрытие событий; `stock-adjustment` — за форму и отправку корректировки. Композиция `_pages` связывает их модальным сценарием и добавляет точку входа из остатков, без импорта одного feature в другой. Успешные команды инвалидируют журнал. Периодическое обновление не сбрасывает ввод.

Сводка журнала всегда общая; фильтры ограничивают только список. Заголовок события показывает чистое изменение общего баланса; внутренние операции обозначены нулём, подписанные строки объясняют переходы стадий и адресов. Названия берутся из исторического события, исполнитель без данных отображается как «Не указан». Начальная точка не выдаётся за восстановление прошлой истории.

В корректировке выбор объекта фиксирует исходные количество и адрес. Затем вводятся факт, причина и сотрудник. Отдельный шаг показывает объект, адрес, до/после и эффект в штуках. Только явное применение отправляет команду. При изменении исходных данных сохранение блокируется, обновление исходной базы выполняется отдельно, факт и причина сохраняются. Серверные и сетевые ошибки оставляют форму открытой. Точный повтор использует прежний requestId, параллельная повторная отправка блокируется.

Пересчёт можно исправить новой записью. Восстановление списанного короба пока отсутствует, и форма прямо сообщает об этом до применения. Списанные короба сохраняются в истории остатков с отдельным статусом.

## Проверка

Мапперы и фильтры проверяются изолированными тестами; сервер остаётся единственным источником складских правил. В браузере проверяются ввод, подтверждение, сохранение, пересчёт баланса, раскрытие события и фильтры на отдельной копии базы.
