# ADR064 — Поставки маркетплейсов в плане сборки

Статус: принято, 2026-10-26.

## Решение

Поставки входят в существующую атомарную загрузку данных. JSON snapshot расширен optional inbound[] и supplies[] без переписывания прежних снимков и без миграции склада. DTO возвращает только проверенные идентификаторы, даты, статусы, названия и количества; raw ответы с контактами не сохраняются. Web использует Swagger → Orval и runtime guard, FSD сохраняется.

План считает inbound отдельно по внешней карточке, затем умножает на unitsPerItem один раз. Неизвестное количество одного товара не блокирует остальные тематики. Старые снимки используют прежнюю схему coverage/stock.inboundUnits. Явное ручное суммарное значение, включая ноль, перекрывает API и сбрасывается после success sync как раньше.

WB загружает все открытые документы статусов2/3/4/6 и завершённые5, обновлённые за30дней. Плановые2/3 не входят в запас. Открытые4/6 используют quantity−readyForSaleQuantity с предупреждением о возможной недостаче;5 использует acceptedQuantity−readyForSaleQuantity. Неизвестные счётчики, битые даты и переданные документы старше30дней дают null затронутым товарам. Факт передачи предпочтителен; резервные даты явно отмечаются.

Ozon загружает заявки v3 list/get и состав v1 bundle для просмотра. Источник количества в пути — исключительно transit_stock_count аналитики. requested_stock_count и количества документов повторно не прибавляются. Отсутствующая аналитика остаётся неизвестной. Даты, не полученные из проверенного поля API, не выдумываются.

Все внешние URL фиксированы; динамический WB goods допускает только числовой ID. Диагностика не содержит URL с ID, тела ответа или секретов. Прежние пределы4мин/180попыток/80МБ сохранены; WB supplies использует общий интервал2,1сек на list/goods/retry. Неполная загрузка не публикуется. Сеть вне SQL lock, затем повторная проверка сессии и версии подключения. Склад, остатки, ledger, ключи и mappings не изменяются импортом. Автосоздания задач и фонового расписания нет.

## Проверка

Fixtures покрывают пустые списки, плановые/переданные/частично принятые/старые поставки, варианты, пагинацию, пропуски и null, повторы, бюджет/отмену, коэффициенты и отсутствие двойного учёта. Сервис проверяет сохранение документов, свежие права и прежнее складское состояние. Живая сверка проводится существующими ключами через обычный интерфейс.

Источники: [WB Supplies](https://dev.wildberries.ru/docs/openapi/orders-fbw#tag/suppliesInformation), [Ozon list](https://docs.ozon.ru/api/seller/#operation/SupplyOrderList), [Ozon get](https://docs.ozon.ru/api/seller/#operation/SupplyOrderGet), [Ozon bundle](https://docs.ozon.ru/api/seller/#operation/SupplyOrderBundle), [Ozon stocks](https://docs.ozon.ru/api/seller/#operation/AnalyticsAPI_AnalyticsStocks).

Живая проверка WB уточнила формат dates.from/till: календарная ISO-дата YYYY-MM-DD по Москве; полный timestamp API отклоняет400. Верхняя граница — следующий календарный день, чтобы включить весь текущий московский день при трактовке till как полуночи. Формат закреплён fixture-тестом.

Обычная загрузка использует заданный settings.historyDays (или явный historyDays команды), без прежнего неявного минимума56дней. Официальный v3/posting/fbo/list допускает максимум100 отправлений на страницу; лишняя история вместе с83 документами превышала общий180-request бюджет. Выбранные28дней плана сохраняются полностью; транспортные ограничения не увеличены. При расширении истории нужна новая загрузка.
