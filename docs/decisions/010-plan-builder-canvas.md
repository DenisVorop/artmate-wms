# ADR 010 — Конструктор помещения на SVG

Статус: принято для третьего рабочего среза.

## Помещение и объекты

План показывает фиксированное прямоугольное помещение из `WorkspaceDto.warehouse`. Размеры не выводятся из содержимого и не увеличиваются при добавлении или перетаскивании объектов. Стены — отдельные SVG-отрезки; активные входы создают в них настоящие разрывы. Входы и проходы не являются конечными адресами хранения и не получают фиктивных остатков или QR.

Активная секция стеллажа рисуется один раз. Адреса ярусов сохраняются в карточке секции. Напольное место рисуется самостоятельно. Архивные секции, адреса, проходы и входы исключаются из оперативной проекции, но остаются в серверном snapshot для корзины и истории.

`x/y` всегда обозначают верхний левый угол внешнего bounding box. `width/depth` остаются исходными размерами. При 90/270° footprint меняет ширину и глубину местами; при 180° габариты сохраняются, но меняется стрелка ориентации. Подписи на плане остаются горизонтальными. Внутренние рейки и маркеры поворачиваются вместе с объектом.

## Взаимодействие

Режим обзора показывает план, остатки и QR. Режим конструктора добавляет палитру «Секция», «Место», «Проход», «Вход», «Размеры склада», «Корзина», а также действия изменения параметров, поворота и архивирования. Добавление выполняется через формы; перетаскивание изменяет геометрию выбранного объекта. Это изменение схемы склада, а не подтверждение физического перемещения паллеты.

Pointer Events переводят экранные координаты в метры через обратную матрицу SVG. Секции, напольные места и проходы привязываются к сетке 0,5 м и ограничиваются внешними границами помещения с учётом rotation footprint. Если точная граница не кратна сетке, граница имеет приоритет. Габариты объекта не уменьшаются автоматически.

Нажатие становится перетаскиванием только после явного `pointermove` минимум на 5 экранных пикселей. Обычный down/up не вызывает геометрических команд даже при изменении прокрутки или матрицы SVG. Выбор объекта обновляется после вычисления конечной позиции на Pointer Up: более короткая боковая карточка не должна менять прокрутку и систему координат в середине жеста.

Перетаскивание входа выбирает ближайшую стену, достаточно длинную для его ширины. Offset считается от канонического начала стены, привязывается к сетке и ограничивается так, чтобы проём целиком оставался на стене. При равном расстоянии предпочтение получает исходная стена. После изменения размера помещения east/south отображаются по новой границе без изменения offset.

Позиция под новый объект предлагается поиском внутри настоящего помещения по повёрнутым footprints. Для хранения учитываются и проходы; для нового прохода — только объекты хранения, поскольку пересечение проходов разрешено. При отсутствии места интерфейс явно предлагает изменить параметры объекта или размеры помещения. Самостоятельного расширения плана нет; сервер окончательно проверяет bounds и конфликты.

Для всех жестов есть числовая альтернатива в формах. Выбор SVG-объекта доступен с клавиатуры через Tab и Enter/Space. Масштаб: вписать помещение и увеличение до 800%, с прокруткой внутри панели. Системный reduced motion отключает анимации.

## Сохранение и восстановление

На время перетаскивания UI хранит только preview. Запись выполняется после Pointer Up; итоговая координата вычисляется по последнему событию, без зависимости от устаревшего React state. Неуспешный запрос убирает preview и возвращает серверную геометрию. Сообщение API остаётся рядом с планом. Повторные записи блокируются на время запроса.

Состояния «сохраняем», «изменения сохранены» и «не сохранено» относятся к подтверждённым запросам. Успех показывается после команды и свежего snapshot из API bridge. Архивирование и восстановление проходят через серверную корзину, а не локальную имитацию Undo. ID и QR сохранены.

## Границы FSD и проверки

- `lib/plan-geometry.ts` — чистая геометрия отображения и подсказок, без складских мутаций.
- `lib/map-view-model.ts` — оперативная проекция активных секций/адресов и фактической занятости.
- `lib/use-map-interaction.ts` — выбор, масштаб, preview, pointer lifecycle и статус сохранения.
- `ui/plan-canvas.tsx` — SVG помещения и объектов.
- `ui/warehouse-layout.tsx` — композиция canvas, согласованных форм и карточек. Операции остаются в `model/use-location-actions.ts`, а контракты берутся из Orval.

Изолированные тесты проверяют повёрнутые footprints, допустимое касание границ, snap/clamp, отсутствие свободной позиции, выбор стены и удержание входа в её границах, реальные разрывы стен и исключение архивных сущностей из плана. Складская валидация и транзакции проверяются отдельно backend-тестами; browser QA выполняется на клоне данных.

## Границы этапа

Помещение прямоугольное, стены не редактируются отдельными вершинами. Проходы — прямоугольники. Зона безопасного доступа к входу, маршрутизация техники и проверка нормативной ширины проходов не моделируются. Перетаскивание не разрешает конфликт автоматически: API отклоняет пересечения с объяснением. Восстановление в занятую геометрию также остаётся в корзине с причиной отказа.
