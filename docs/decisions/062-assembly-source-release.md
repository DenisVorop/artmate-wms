# 062. Адрес сырьевой паллеты освобождается при сборке

Когда последний товарный скан расходует исходную raw-паллету до нуля, scanTask в той же транзакции переводит её в retired и очищает locationId и returnLocationId. Адрес доступен сразу, без ожидания завершения короба, задания или отгрузки. Завершённое понижение с резервом возврата также освобождает верхнюю ячейку. Паллета с оставшимся незарезервированным товаром остаётся на хранении.

Сохраняются идентичность паллеты, SKU/партия, исходный адрес размещённой строки приёмки и происхождение раскрасок в коробах. После исчерпания резерва сотрудник сканирует следующую FIFO-паллету обычным способом. Никаких фиктивных сканов вывоза: activity сообщает освобождение адреса после сборки. Статус retired в общем списке называется «Снят с хранения».

Переход входит в обычный command lock/replay и stocktake cell versions: последний raw −1 с исходным адресом и WIP/box +1 сохраняют количество партии, отдельного количественного списания нет. Ошибка упаковки откатывает количество, статус, адреса, историю и версии ячеек вместе. Replay не повторяет освобождение. Факт выработки появляется только при закрытии короба.

Правило уточняет ADR006/037 только для расхода сырья при сборке. Нулевой остаток после корректировки/инвентаризации сам по себе не доказывает снятие физического поддона. Finished и общая паллета сборки сохраняют свой жизненный цикл. Автоматического обнуления всех адресов при запуске или миграции нет.

Старые нулевые паллеты исправляются только точечно после проверки последнего количественного события assembly, нулевых резервов и отсутствия последующих физических подтверждений/перемещений. Перед исправлением — резервная копия; под общей SQL-блокировкой меняются только status/locationId/returnLocationId, версии затронутых адресов, revision и новое activity с явной причиной исправления. Старые ledger, work_events, commands, приёмки и история инвентаризаций не переписываются.
