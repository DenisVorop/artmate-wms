# 040. Серверные права, авторство и проекция рабочего места

Дата: 24.10.2026. Статус: принято.

## Граница доверия

Все складские HTTP endpoints, включая QR/этикетки, закрыты глобальным `AuthGuard`; неизвестная операция по умолчанию запрещена. Swagger UI и JSON/YAML доступны только вошедшему manager. Контекст HTTP обязателен и создаётся middleware через `AsyncLocalStorage`. Прямые доменные unit tests продолжают использовать доверенный сервис без HTTP; внешнего переключателя обхода нет.

`AuthService` использует `WarehouseService.authTransaction`: ту же базу, очередь и транзакционную блокировку PostgreSQL. Второго PGlite или параллельного хранилища сессий нет. Перед складской мутацией и до чтения cached response сервер повторно проверяет сессию, свежую роль, CSRF, разрешение операции и владельца задания внутри SQL-транзакции. Отзыв между guard и командой не позволяет вернуть старый ответ.

Fingerprint новых HTTP-команд включает account ID и employee ID вместе с операцией и телом. Чужой requestId нельзя использовать для получения чужого ответа или выполнения второй команды. Прежние fingerprint доверенных доменных команд и старые cached responses не переписываются. Проекция ответа применяется после мутации и после replay; прежний полный ответ manager не превращается в утечку после понижения аккаунта.

## Политика

Manager управляет планом склада, тематиками, приёмками, заданиями, отгрузками, сотрудниками, аккаунтами и корректировками; читает полный склад и журнал. Может планировать движение или назначать сборку другому сотруднику. Это назначение исполнителя, а не подмена автора.

Работник читает складские остатки, карту, свободную очередь и свои задания; размещает входящие паллеты, печатает доступные этикетки, берёт сборку и размещение, сканирует, упаковывает, ставит свою работу на паузу и меняет свою смену. Может создавать перемещение для себя, подтверждать только свои движения и вывозить пустую паллету на своей рабочей смене. Управленческие изменения, журнал и аккаунты ему недоступны.

Для реальной работы все роли обязаны передавать собственный employeeId там, где он предусмотрен DTO. Сканирование, упаковка и физические take/place доступны только назначенному исполнителю, в том числе для manager. Manager может отменить чужое ещё не начатое движение: это освобождение резерва, без подтверждения физического действия. Работник отменяет только своё. Вывоз пустой паллеты не добавляет новый employeeId в прежний DTO: исполнитель берётся из сессии, смена проверяется сервером. Менеджер может менять смену другого сотрудника как управленческое действие.

## Ответы и безопасные подсказки

Рабочая проекция содержит только самого сотрудника, свои задания и свободную неназначенную очередь сборки, свободные/свои размещения, свои движения и активные приёмки. `shipments` и `activities` пусты. Тематики, партии, паллеты, короба, адреса и общий баланс читаются для складской работы.

Optional `addressHolds` сообщает анонимные резервы адресов (`movement`, `putaway`, `return`) из полного состояния до фильтрации. В нём нет чужих employee/task IDs. Это вычисляемое поле, оно не сохраняется в складские таблицы. Оно не позволяет карте показывать чужую удерживаемую ячейку свободной.

Серверные placement-options используют полный склад под повторной проверкой доступа. Иначе скрытое в рабочей проекции чужое движение могло бы ошибочно освободить адрес в подсказках. Работник не получает options чужого взятого размещения или завершённой приёмки. Все реальные мутации снова проверяют физику и резервы по полному состоянию.

## Авторство

Автор каждого нового количественного события берётся из текущего account employeeId, независимо от `employeeId` в назначении задания или движения. В новых HTTP `ActivityDto` добавляются optional `actorEmployeeId`/`actorName`; прежние события сохраняются без переписывания и выдуманного автора. Секреты аккаунтов в складское состояние и cached responses не входят.

Проверки охватывают подмену body actor, планирование другим исполнителям, физическую работу только назначенного человека, полную цепочку приёмка→сборка→размещение→перемещение→отгрузка, авторов ledger/activity, анонимные чужие резервы и проекцию повторного ответа после смены роли.
