# 045 — Интерфейс документа инвентаризации

Дата: 2026-10-24. Статус: принято.

## Документ и последствия

`/stocktakes` доступен обеим ролям. Менеджер создаёт документ по помещению/коридору, секции или явному списку адресов. Три способа выбора видны одновременно (`rule/control-matches-cardinality`); отправляется разрешённый список от 1 до 200 действующих rack/floor ячеек. Для помещения учитывается полное попадание повёрнутого контура адреса внутрь участка. Ярусы секции остаются отдельными адресами. Заблокированная для размещения ячейка не исключается из инвентаризации.

Состав выбора показан до создания. Список адресов зафиксирован при открытии формы и обновляется отдельной кнопкой; polling не меняет выбранную область без ведома пользователя. Сотрудник самостоятельно берёт свободный документ и считает только собственный документ на рабочей смене. Серверные `can...`, `stale` и `busyReasons` управляют доступностью; клиент не пытается самостоятельно разрешать складские резервы.

Подсчёт, передача на проверку и отмена не меняют товар. Только именованное утверждение менеджером применяет полный preview с причиной (`rule/name-object-scope-consequence`, `rule/irreversible-action-safeguard`). Интерфейс показывает изменения по каждому коду, исходный/целевой адрес, количество и изменение единиц товара. Внутренние переносы имеют нулевое изменение общего количества. После утверждения показывается сохранённый результат документа, а не расхождение с будущими остатками.

До явного подсчёта всех ячеек таблица изменений и суммарный unitsDelta скрыты: отсутствие подсчёта не интерпретируется как пустая ячейка или подтверждённая недостача. Показаны прогресс и объяснение, что расхождения появятся после полного подсчёта; реальные блокирующие issues остаются видимыми. Явно подтверждённый пустой факт считается завершённым подсчётом. Исторический approved-результат показывается всегда.

## Факт не равен ожиданию

Снимок остатка — справка. Новый подсчёт не копирует ожидаемое количество в фактическое и не отмечает короба найденными. Сотрудник вручную вводит/сканирует код ячейки и явно подтверждает осмотр перед сохранением, в том числе для пустой ячейки.

Для известной сырьевой паллеты есть отдельное поле «Паллета найдена здесь». Если она найдена, количество обязательно: пустое поле не превращается в 0. Найденная пустая паллета имеет present=true и количество 0. Если не найдена, строка остаётся видна в форме, но не включается в rawPallets API. Это позволяет корректно зарегистрировать перенос той же известной паллеты между двумя пересчитанными адресами документа, не объявляя её одновременно присутствующей на исходном адресе. При отсутствии подтверждённого переноса API предложит недостачу по своим правилам.

Готовые короба отмечаются по уникальным кодам; другой найденный код добавляется отдельным полем. Неизвестные коды сохраняются для проверки как расхождение; интерфейс не создаёт для них товар, партию или новый короб. Сохранённый факт можно открыть повторно как факт, но подтверждение осмотра снова требуется.

## Конкурентные изменения и восстановление

Склад продолжает работать. Устаревшая или занятая ячейка имеет явное объяснение; подсчёт сохраняет введённые данные и блокирует запись до допустимого состояния. Refresh обновляет только выбранную ячейку. Если уже есть подсчёт или несохранённый ввод, сначала показано предупреждение о переносе старого факта в историю и повторном подсчёте. Refresh из review возвращает документ в работу, после чего нужен новый submit. Без введённого факта дополнительное подтверждение не требуется (`rule/destructive-proportional`).

Форма фиксирует expectedRevision документа при открытии. Polling не подменяет эту версию молча. Если обновился только другой адрес, пользователь явно принимает новую версию без повторного ввода. Если изменились baseline или прежний факт самой ячейки, ввод сохраняется, а сброс и загрузка актуальной ячейки выполняются только после предупреждения. Утверждение, отмена и refresh с подтверждением также сохраняют проверенную версию (`rule/preserve-user-input`).

Переключение документа с несохранённым вводом требует явного решения. При отмене явно названа потеря локального несохранённого ввода и количество затронутых ячеек; обещание сохранения относится только к сохранённому факту и истории. Подсчёт остаётся смонтированным при сворачивании адреса. Активные документы отделены от архива approved/cancelled серверным bucket с честной пагинацией. Поиск явно ограничен текущей страницей. Обработка, проверка и подтверждение размещены на странице, без вложенных модальных окон (`rule/inline-before-modal`, `rule/no-nested-modals`).

## FSD и запись

`entities/stocktake` содержит типизированные GET hooks: polling 5 секунд, AbortSignal, отдельные ключи списка/документа/preview. При выборе другого документа старый placeholder не показывается. `features/stocktakes` содержит RHF/Zod формы, UI-state, мапперы и отдельную модель команд. DTO и клиент получены Orval из Nest Swagger.

POST используют общий replay-safe transport, не обходя auth или защиту requestId. Feature orchestration проверяет auth epoch до записи, после каждого await и перед cache/callback. При успехе команды сбой последующей отмены чтений или refresh не превращается в ошибку сохранения. Старый replay не понижает revision кешированного документа. Все складские и документные read-кеши инвалидируются; складской Workspace не используется как ответ документной мутации.

## Проверки

Scoped tests покрывают повёрнутые границы scope, архивные/служебные адреса и ярусы, лимит 200 адресов, причины, отсутствие автоподстановки фактов, явный ноль/пустой осмотр, уникальность кодов, paired relocation source absent/target quantity, сохранённый факт, старый replay, смену auth scope и сбои postcommit read orchestration. Общий typecheck/FSD и браузерные сценарии проверяются при интеграции этапа.
