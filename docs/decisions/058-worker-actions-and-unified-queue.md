# 058. Действие сотрудника, два скана и общая очередь

Проблема подтверждена владельцем при тестировании: исходный адрес визуально перекрывает короб, действие скрыто в label сканера; повторные QR мешают переносу, задания распределены по разным страницам.

## Действие и объект

Последнее уточнение владельца: при размещении с общей паллеты нельзя заранее назначать конкретный короб — нужно разрешить любой. До выбора заголовок «Возьмите любой короб» и инструкция скана, без номера, который сотрудник должен искать. После выбора показываются тематика и различимый номер фактически взятого короба. При переносе главный заголовок «Поставьте короб» и адрес назначения; уже взятый короб остаётся в контексте. Крупный блок и инструкция скана соответствуют одному текущему действию, а не показывают весь маршрут одинаковым весом. Основание: запрос владельца, product-design rule/one-primary-action, rule/name-object-scope-consequence и rule/preserve-mental-model.

## Два физических подтверждения

Вход в зону и завершение оставляют idle-binding с jobKind/jobId null. UI определяет готовность по zone.kind=putaway. Скан вызывает takeAnyPutawayBox с boxCode; API ищет настоящее ожидающее задание именно этого короба, проверяет принадлежность источника зоне, исполнителя и смену, атомарно резервирует подходящий адрес и фиксирует in_transit. Старое своё claimed при другом выборе освобождается той же транзакцией; чужое назначение и короб в пути защищены. Неизвестный, уже размещённый или несовместимый короб отклоняется без изменения прежнего выбора. Скан адреса вызывает placePutawayBox с locationCode; переносимый короб уже выбран серверным заданием, повторный скан не требуется. При перезагрузке в пути сразу запрашивается назначение. Исходный QR не подставляется клиентом и не объявляется просканированным. Старые id-based takePutawayBox и take/place с парой кодов сохраняются для совместимости. Обе ветки используют общие проверки и переходы, одну атомарную запись ledger/workforce и обычный replay. Основание: явный запрос убрать повторы, rule/no-redundant-entry, rule/smallest-intervention и rule/cover-reachable-states.

## Общая очередь

entities/work-queue строит представление из существующих серверных документов. Новый read endpoint и дублированная таблица заданий не нужны. Приёмка представлена каждой ожидающей паллетой; сборка, размещение, перемещение, отгрузка и инвентаризация сохраняют собственные статусы и документы. Отдельные данные инвентаризаций загружаются своим существующим query. Проекция сервера сохраняет границы видимости сотрудника.

Руководитель видит общий экран с фильтрами, сотрудник — единый список со своего рабочего места. Просмотр не подтверждает физическую работу и не перехватывает текущий скан. Переход к виду работы не выдаёт себя за выбор произвольного задания, если существующая очередь выбирает следующую задачу по своим правилам. Carrying/dirty/pending-проверки сохраняются. Основание: владелец подтвердил обе роли, rule/navigation-vs-action, rule/preserve-user-input и rule/cover-reachable-states.
