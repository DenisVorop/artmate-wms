# ADR 047 — Рабочие переносы на телефоне

Принято: 24.10.2026.

## Решение

`features/employee-handling` публикует `EmployeePutaway`, `EmployeeReceiving` и `EmployeeMovements` с одинаковыми props `{data: WorkspaceDto, onIdle: () => void, onProblem?: (message: string) => void}`. Компоненты не включают управленческое планирование, назначение исполнителя, создание перемещений или вывоз пустой паллеты.

Фактический исполнитель всегда из `useSession().user.employeeId`; мутации проходят через общий `useWarehouseCommands`. UI-state и приоритеты находятся в `lib`, выполнение команд и подбор адресов — в `model`, представление — в `ui`. Соседние features не импортируются; DTO и клиент берутся из Orval.

В работе всегда одно выбранное задание. Своя переносимая паллета/короб приоритетнее назначения без забора; свои задания приоритетнее свободной очереди. Свободное размещение берётся явно. Новое задание после завершения открывается отдельной кнопкой и не захватывается автоматически. Выбор сохраняется при polling; исчезнувшее задание требует явного обновления выбора.

Перенос подтверждается двумя реальными сканами: короб/паллета, затем адрес. Первый скан проверяет идентичность выбранного объекта и не меняет склад. Существующий API принимает оба скана одной атомарной take/place-командой после скана адреса. Ожидаемые коды не подставляются вместо сканов; QR и текстовый код соответствуют текущему серверному формату. Ошибка API сохраняет первый скан и непринятый ввод в общем `EmployeeScan`. Смена задания/этапа/исполнителя создаёт новый контекст ввода.

Приёмка предлагает паллету старейшего незавершённого документа и позволяет выбрать другую неразмещённую паллету этого документа короткими карточками. Рекомендация адреса является подсказкой, не резервом и не приходом товара. Остаток меняется только после успешной серверной команды. Подбор использует AbortSignal, auth epoch и отдельный query key с областью личности; устаревший ответ другой сессии не принимается.

Во время физического переноса кнопка возврата к основному заданию скрыта; остаётся объяснение обязательного размещения и сообщение о проблеме. До забора добровольное размещение можно вернуть в очередь. Предварительные UI-проверки не заменяют повторную проверку доступности/прав/смены сервером.

## Проверка и пределы

Чистые тесты проверяют приоритет физического переноса, чужое назначение, добровольную очередь, фактическую дату приёмки, формат QR, отсутствие мутации входных массивов и запрет конкурирующих действий. UI использует существующие токены графитового стеклянного интерфейса и общий сканер ввода. Реальная работа без сети или физическая проверка HID-оборудования не заявляется.
