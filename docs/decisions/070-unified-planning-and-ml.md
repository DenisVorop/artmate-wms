# ADR070: единый план, очередь впрок и проверяемое машинное обучение

Дата: 2026-10-26. Статус: принято.

## Задача
Раньше одно число сборки скрывало будущую отправку и остаток своего склада; короткая история новинок усреднялась по дням до появления. Пользователь просит единый план и ML, отдельно уточнив: фиксированного локального запаса в днях не нужно, сотрудник работает 5/2 и должен видеть следующую полезную работу.

## Решение
1. Nest рассчитывает независимые цели каждой площадки из дневного прогноза до отправки, доставки, периода продаж и страховки. Из каждой вычитаются только её остаток и её inbound, результат округляется в полные короба. Выбранный день недели — настройка; ближайшая дата вычисляется по Москве.
2. Публичная строка разделяет потребность отправки, оставшийся собственный товар, недостаток товара и сборку с учётом НЗП. Старые поля taskcommand сохраняются. Unknown/partial/stale блокируют авторитетную рекомендацию и не входят в общий итог. Нераспределённый положительный manual transit и отгрузочные резервы без назначения не становятся выдуманным распределением по площадкам.
3. Фиксированный локальный резерв не вводится. Отдельная очередь рекомендует следующий короб по прогнозируемому покрытию, сезонному контексту и ограничениям. Свободная ёмкость проверяется реальными putaway rules; сначала учитываются готовые неразмещённые короба и НЗП. Без адресов у текущих остатков нет надёжной оценки свободных мест. Минимальный остаток SKU — явная отдельная политика.
4. Создание optional-задания — только явная manager-команда purpose=backlog, один короб, свежие проверки исходных данных, вместимости, сырья и proposalHash под lock. Ordinary purpose=urgent совместим со старой командой. Никаких автоматических эффектов/заданий/поставок.
5. Adaptive baseline использует известные наблюдения и ограниченный недавний тренд. ML — локальная авторегрессия с Ridge-регуляризацией. Обучение/признаки/валидация используют только префикс; ML применяется после устойчивого выигрыша минимум 5%, в том числе на текущем горизонте. Годовые модели не обходят прежний порог истории. Короткая история может честно оставить baseline.
6. Новый год без достаточной годовой истории получает только ограниченный наблюдаемым ростом календарный сценарий с отдельной подписью. Сценарий не считается выученной сезонностью.
7. FSD web отображает DTO → Swagger → Orval и проходит runtime guards; решения о доступности команды остаются на сервере. Главный экран показывает три результата, источники и редкие настройки раскрываются.

## Инварианты
Импорт/ML/пересчёт не меняют Warehouse, ledger, FIFO, QR или выработку. Собственные 322 короба из агрегатного пересчёта сохраняются без фальшивых коробов/адресов. Результаты уже пройденного теста сканера не переписываются. Старые JSON читаются с additive defaults; версия модели и входной ключ инвалидируют старый кэш. Внешние сервисы ML не подключаются.

## Ограничения
Нет исторических региональных продаж и достоверного расписания/производительности будущих смен. План по площадкам не обещает кластерную оптимизацию или почасовую загрузку сотрудника. Неизвестная реальная вместимость требует адресного учёта. График 5/2 объясняет непрерывную очередь, но не доказывает потребность заполнять весь склад.
