# ADR 015. Формы участков и входы в локальных координатах

Дата: 23 октября 2026. Статус: реализовано для этапа отдельных помещений.

## Участок и рабочее поле

Рабочее поле (canvas) и реальный пол склада разделены. Диалог «Размеры плана» меняет name/width/depth общего поля и не меняет размеры помещений/коридоров. Его маппер не отправляет массив spaces или layoutMode. В режиме spaces пол существует только внутри активных нарисованных участков.

SpaceForm получает серверный участок или черновик рисунка kind/x/y/width/depth. До сохранения черновик не становится складскими данными. Имя обязательно; координаты глобальные; оба размера от 0,5 м. Метровые поля используют step=any и не округляют числа к сетке жеста. Zod проверяет конечность, границы поля и предварительные пересечения; сервер повторяет полную проверку транзакционно. Касание стен допустимо. UI не генерирует ID участка и не отправляет archived/archivedAt.

Тип участка выбирается нативными radio «Помещение» / «Коридор», оформленными сегментами: две альтернативы видны одновременно, доступны стрелками клавиатуры. Это применение `rule/control-matches-cardinality`, `rule/accessible-name-required`, `rule/keyboard-complete-flow`. Числовые поля являются полной альтернативой рисованию: `rule/gesture-has-control-alternative`.

## Удаление и корзина

SpaceDetails показывает тип, имя, размеры, площадь и положение. В конструкторе доступны редактирование и «Удалить участок с плана». Наличие активной секции (в том числе без ярусов), самостоятельного адреса, прохода или привязанного входа даёт видимую причину блокировки. Предварительная оценка UI не подменяет серверную проверку next state.

Удаление является мягким архивированием без дополнительного подтверждения. Корзина содержит space:id наравне с другими объектами, восстановление сохраняет серверный ID. Вход с архивным родительским участком ждёт восстановления этого участка. Применяются `rule/destructive-proportional`, `rule/name-object-scope-consequence`, `rule/undo-only-when-honest`. Нет hard delete, таймера восстановления и автоматического восстановления зависимых объектов.

## Входы и общие стены

EntranceForm в spaces показывает выбор только активных помещений/коридоров. Required response spaceId хранится в форме явно. В rectangle допустим только null, проём относится к прежнему общему контуру. В spaces требуется ID активного участка. Wall/offset/width считаются относительно выбранного участка; длина стены в карточке и в форме берётся у участка, а не у canvas.

Новый вход получает предлагаемый свободный проём в активном участке. Для предложений и предварительной проверки проёмы переводятся в глобальную ось стены: один физический проём на общей границе нельзя продублировать, выбрав соседний участок и противоположную стену. Изменение существующего входа исключает его собственный ID из проверки. Архивные проёмы не занимают стену.

Форма не выдумывает привязку legacy-входов. Первый createSpace включает spaces mode на сервере атомарно. Сервер может безопасно сохранить старые ID входов, если вся прежняя глобальная стена/проём точно совпадают с границей нового участка; иначе отклоняет команду. UI сохраняет введённые значения и показывает полученную причину.

## Состояния и архитектура

Сброс формы происходит при открытии либо смене редактируемого ID. Snapshot polling не стирает ввод. Ошибка оставляет форму и черновик доступными для исправления — `rule/preserve-user-input`, `rule/error-states-recovery`. Pending блокирует поля/отправку/закрытие, подписи действий стабильны и помечены aria-busy. При отсутствии активных участков вход нельзя сохранить; форма объясняет необходимость сначала нарисовать пол — `rule/cover-reachable-states`.

FSD сохраняется: схемы/мапперы/defaults/предварительные guards в feature/lib, формы и карточки в feature/ui, состояние и команды интегрирует основной composer/model. Типы WarehouseSpaceDto/CreateSpaceDto/EntranceDto берутся из generated Orval. Используется существующая корзина и server source of truth; локальный кэш не хранит самостоятельный склад.

## Проверки

Тесты проверяют точные дробные размеры и конечность чисел; перенос черновика и исключение ID/архивных флагов из CreateSpaceDto; касание, пересечение и выход за canvas; защиту участка активными объектами и входами; восстановление участка/зависимого входа в корзине; required локальный spaceId, архивную привязку и rectangle-null; совпадение физического проёма с разных сторон общей стены. Браузерная проверка рисования, сохранения и восстановления проводится root на отдельном preview.
