# ADR 081 · Первичная инвентаризация при внедрении WMS

Дата: 2026-10-27. Статус: принято по уточнению пользователя.

## Проблема

Физический товар существовал до WMS. Обычная сверка принимает только известные паллеты/короба и не может быть способом запуска системы. Использовать новую приёмку или мнимую сборку означало бы выдумать историю и выработку.

## Решение

Добавить mode=opening в существующий жизненный цикл инвентаризации: queued → counting → review → approved. Старые документы без поля остаются recount. Адреса первичного документа должны быть пустыми и свободными в WMS. Пустой результат — явный осмотр, отсутствующий результат не ноль.

Ввод: одна европаллета 1200×800 мм и одна тематика на адрес. Сырьё — количество штук, фактическая дата поступления, полная высота и при необходимости масса; готовые короба — число коробов по датам партий и штук в коробе. Физика, лимиты, занятость, архив и версии проверяются на каждом переходе. Уже учтённый товар не заменяется и не дублируется.

Только утверждение создаёт начальные партии, паллеты и короба с provenance openingStocktakeId. packedAt старых коробов неизвестен и равен null; registeredAt — дата учётного ввода. FIFO определяется реальным receivedAt партии. Количества записываются как opening_balance со ссылкой на документ. Начальный ввод не создаёт receipt, assembly, putaway или work_events.

Ранее подтверждённый безадресный готовый остаток уменьшается на зарегистрированную часть без двойного прибавления к плану. Частичный ввод не доказывает полноту. Дополнительное явное подтверждение руководителя по SKU закрывает его начальный подсчёт и заменяет прежнюю оценку фактическим учтённым итогом. История подтверждений append-only, операция атомарна с утверждением.

QR печатаются только после утверждения, из существующих Label API, с реальными ID новых объектов. Печать по адресу, ограниченными страницами с ожиданием всех выбранных QR. Новые DTO — Nest → Swagger → Orval; UI в прежнем FSD срезе stocktakes. Пока начальный документ открыт, автоматическая сборка ожидает завершения ввода.

## Совместимость

Новые поля payload additive; новые таблицы не требуются. Старые ответы, склад, auth, ledger и выработка не переписываются при обновлении. Нормальная сверка неизвестных кодов по-прежнему не создаёт излишки.
