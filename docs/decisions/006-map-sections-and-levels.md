# ADR 006 — Секции стеллажей и конечные адреса ярусов

Статус: принято для второго рабочего среза.

## Модель и отображение

Стеллажная секция `RackSectionDto` — самостоятельный объект плана с геометрией в метрах. Каждый её ярус — самостоятельный `LocationDto` с `sectionId`, номером `level`, ограничениями и постоянным идентификатором адреса. На одном конечном адресе размещается одна физическая паллета. Старое поле `Location.levels` не используется для построения интерфейса.

SVG рисует секцию ровно один раз. Боковая карточка перечисляет реальные ярусы, их адреса, фактический остаток и вместимость. Выбор яруса открывает его полезные размеры, ограничения массы, стороны доступа, паллеты и QR. Верхний статус секции подписан номером выбранного яруса, чтобы свободный первый ярус не создавал впечатления свободной секции целиком.

Отдельные напольные места и рабочие зоны имеют `sectionId=null` и собственный объект на плане. В том числе поддержана зона отбора `picking`: у неё четыре стороны доступа. В форме это значение закреплено; сервер остаётся окончательным валидатором.

Это решение заменяет ограничение первого среза из ADR 004 о суммарном адресе нескольких ярусов. Адреса и QR существующих первых ярусов сохраняются серверной миграцией.

## Сценарии конструктора

- Создать секцию: геометрия, код и название секции, массив профилей реальных ярусов. Каждый профиль имеет собственный адрес и название, полезную ширину/глубину/высоту, вместимость готовых коробов, необязательный лимит массы и стороны доступа. Допускается до 20 ярусов, согласно контракту API.
- До создания секции можно добавить/убрать профили или подставить адреса вида `A-01-02`. Это черновик формы, а не удаление существующих адресов.
- Добавить ярус существующей секции: отдельная команда `createRackLevel`. Следующий номер назначает сервер. Новый профиль по умолчанию копирует ограничения верхнего существующего яруса; адрес и название предлагаются для нового номера.
- Настроить секцию: `updateRackSection` меняет её геометрию и синхронизирует геометрию адресов сервером. Перетаскивание секции вызывает эту же команду после Pointer Up. Привязка к сетке — 0,5 м.
- Настроить ярус: `updateLocation` меняет только адрес, название, физические ограничения, стороны доступа и блокировку. Геометрия яруса отдельно от секции не редактируется.
- Создать/настроить напольное место или зону: `createLocation`/`updateLocation`, включая собственную геометрию и полезные габариты.

Все формы используют React Hook Form + Zod. Черновик сохраняется при фоновом обновлении snapshot. Отказ сервера оставляет форму открытой и показывает его причину. Успешная команда получает свежий snapshot через инфраструктурный bridge; интерфейс не использует исторический ответ идемпотентности как актуальные остатки.

## Физическая занятость и резервы

Паллета со статусом `stored` занимает адрес даже при нулевом товарном остатке. Интерфейс показывает такую паллету и поясняет необходимость подтверждения физического вывоза. `in_transit` с `locationId=null` не изображается на старом адресе. `retired` не учитывается как физическая занятость.

Адреса целей активных перемещений (`planned`/`in_transit`) и удержанные `pallet.returnLocationId` выделены как резервы. В карточке указаны код перемещения и паллеты. Пустой адрес с резервом не подписывается свободным. Остатки коробов берутся из фактических `stored` коробов конкретного адреса; не выводятся из количества на паллете умножением упаковки.

## Границы FSD

- `lib/location-form.ts`, `lib/rack-form.ts` — схемы форм, значения по умолчанию, мапперы в generated DTO.
- `lib/map-view-model.ts` — только проекция серверного snapshot для SVG, адресной карточки и статусов. SDK enums используются напрямую.
- `lib/use-layout-state.ts`, `lib/use-map-interaction.ts` — локальное состояние выбора, диалогов, масштаба и перетаскивания.
- `model/use-location-actions.ts` — сценарные вызовы общего typed API bridge; `model/use-location-label.ts` — получение этикетки.
- `ui` — формы, SVG и карточки. Публичный API feature по-прежнему `WarehouseLayoutFeature`.

## Проверки и границы

Клиент не дублирует складской алгоритм геометрической совместимости или резервирования. Сервер проверяет занятые и зарезервированные адреса при изменении ограничений, геометрии и размещении. На плане показываются прямоугольные секции; автоматическая проверка ширины проходов, маршруты техники, поворот секций и 3D не входят в этот этап.

Архивирование и удаление существующих ярусов не добавлены. Печать выполняется для конкретного конечного адреса, а не для секции целиком. На мобильном экране SVG прокручивается внутри панели, карточка адреса располагается ниже; управление с клавиатуры и reduced motion сохраняются.
