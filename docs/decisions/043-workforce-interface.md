# 043 — Отчёт по сменам и фактической выработке

Дата: 2026-10-24. Статус: принято.

## Границы данных

Экран `/performance` использует отдельные API чтения `getPerformance`, `getShiftHistory`, `getWorkHistory`. Типы и клиент генерируются Orval из Nest Swagger. История не вычисляется из текущего Workspace и не использует прежние накопительные `boxesToday` / `unitsToday`.

Период — календарные даты `YYYY-MM-DD` включительно в `Europe/Moscow`. Начальное значение — сегодняшний день по Москве; пресеты включают сегодня и предыдущие 6 или 29 дней. Ручные даты валидируются как реальные календарные даты, начало не позже окончания, максимум 366 дней. В API уходят даты без преобразования в локальный часовой пояс браузера. Сервер повторно проверяет диапазон и права.

`metrics` и длительности истории относятся только к выбранному периоду. `currentShift`, `currentJobs` и статус сотрудника всегда описывают текущий момент и показаны в отдельном блоке «Сейчас». Длительность текущей смены относится ко всей этой смене. Время `workingSeconds` подписано «В смене без перерывов»: простой или активность между операциями не измеряются.

Количество раскрасок — `unitsPacked` из состава фактически закрытых коробов, без предположения о фиксированных 20 штуках. Скан источника, короба и отдельной раскраски не считается отдельной единицей выработки. Приёмка, размещение и перемещение учитываются после подтверждённого завершения соответствующей операции.

`trackingSince` постоянно виден. Если период предшествует границе учёта или пересекает её, интерфейс явно сообщает о недоступной части истории: нулевой результат не объявляется отсутствием работы. Смены `observed_from_migration` помечены как зафиксированные при включении учёта; их более раннее начало не восстанавливается. Отсутствующий автор не выдумывается.

## Взаимодействие

Менеджер может выбрать сотрудника или всех сотрудников. `initialEmployeeId` позволяет открыть отчёт из карточки команды. Сотрудник видит только себя, без выбора чужого сотрудника; клиент принудительно использует свой employeeId, сервер независимо ограничивает область данных.

Ручная форма имеет отдельные черновые и применённые значения. Фоновый опрос каждые 5 секунд не сбрасывает ввод. Пресет применяет готовый период, сохраняя выбор сотрудника. При смене фильтров старый placeholder скрывается целиком до ответа; при неудачном обновлении того же запроса последняя версия остаётся с явным предупреждением. При ошибке ввода запрос не отправляется. Пагинация смен и событий независимая и сбрасывается при новом периоде/сотруднике.

Сравнение сотрудников — фактическая таблица без рейтинга, норм и оценки производительности. Выбор имени раскрывает подробности под таблицей. Длительности показываются в часах и полных минутах; положительная длительность менее минуты обозначена «<1 мин». Границы смены/отрезка показаны полностью, длительность ограничена отчётным периодом.

## Архитектура и проверка

`entities/workforce` содержит типизированные read hooks и общие календарные функции. `features/workforce-report` содержит фильтры, состояние выбора/пагинации, мапперы и UI. Публичный `useWorkforceReport` используется также карточками команды. Запросы используют общий префикс `workforceQueryKey`, AbortSignal, polling и общий auth-epoch transport. Ни складской snapshot, ни read cache не служат источником истории.

Scoped tests проверяют московскую границу суток, включительность пресетов, календарную валидность, лимит периода, принудительный собственный scope сотрудника, фактические unitsPacked, агрегирование без раннего округления, формат длительностей и границу доступной истории. Проверки API/миграции и браузерные сценарии выполняются при интеграции этапа.
