# 063. Внешние остатки и предложения на сборку

Первый срез — Wildberries FBW и Ozon FBO. Пользователь подтвердил продажи со складов маркетплейсов. FBS не импортируется. Адаптеры читают только фиксированные официальные HTTPS endpoints; актуальные схемы, отключённые legacy методы, ограничения и источники описаны в [исследовании](../tasks/2026-10-25-marketplaces/provider-findings.md). Проверка фикстур не означает проверку реального кабинета.

## Независимость учёта

Schema14 добавляет шесть отдельных JSONB-таблиц: marketplace_connections, marketplace_snapshots, marketplace_mappings, marketplace_settings, marketplace_transit, marketplace_task_origins. Миграция не создаёт подключений, ключа шифрования, заданий или начальных остатков. Импорт не меняет WorkspaceDto, складской баланс, FIFO, ledger, адреса или QR. В случае недоступности площадки ручная работа склада продолжается.

Снимок заменяется целиком только после полной загрузки каталога, текущих остатков и когорты заказов. Частичная загрузка и ошибка сохраняют последний полный снимок и блокируют новые задания по прогнозу. Неизвестные остатки и входящие поставки не равны нулю. Снимок старше 24 часов считается устаревшим. Синхронизация пока запускается вручную; автоматического расписания нет.

## Сопоставление и расчёт

Внешняя идентичность: WB nmID, Ozon SKU. Руководитель явно сохраняет связь карточки с тематикой и число раскрасок в одной продаваемой единице. Совпадение единственного штрихкода только предлагает выбор. Несколько карточек могут ссылаться на одну тематику; единицы сначала переводятся в раскраски, затем суммируются по площадкам.

Первый прогноз объясним: за последние N полных московских дней суммируются заказанные единицы минус текущие отмены этой когорты. Средний спрос умножается на горизонт + страховые дни + срок доставки. Это оперативный спрос, а не финансовая выручка или точные выкупы. Ozon FBO postings не дают полного финансового учёта возвратов. Сезонность, акции и исторические дни отсутствия товара пока не восстановлены.

Из цели вычитаются доступный остаток площадок, подтверждённый товар в пути, собственные закрытые короба и оставшийся объём уже открытых сборочных заданий. НЗП входит в оставшийся объём задания один раз. Готовые короба включают общий накопитель и короб в пути при размещении; возможность отгрузки показывается отдельно и требует размещённого finished-поддона. Зарезервированные черновиком отгрузки короба учитываются отдельно ровно один раз. Ручной «товар в пути» означает уже отправленный товар, не эти черновики.

Если все связанные API-строки достоверно сообщают поставки в пути, берётся их сумма. Иначе руководитель подтверждает суммарное количество, включая явный ноль. Ручное значение перекрывает API и сбрасывается после успешной синхронизации, замены ключа или изменения набора включённых подключений. Доставка покупателю WB не считается входящей поставкой. Отсутствие строки остатков не подтверждает ноль.

Рекомендация округляется вверх до целых коробов. Доступное сырьё ограничивает создание задания, но не подменяет расчёт потребности. Неразмещённая приёмка, зарезервированное сырьё, недоступные адреса и паллеты в перемещении исключаются. Вместимость готового хранения и производственная мощность пока автоматически не планируются: адрес проверяется обычным процессом размещения.

## Создание задания

Нажатие «Создать задание» повторно проверяет сессию руководителя, свежесть снимка и hash предложения под общей SQL-блокировкой. Общий метод WarehouseService создаёт обычное queued-задание без исполнителя, с теми же FIFO-резервами, что ручная сборка. Состояние, revision, версии ячеек, происхождение forecast и идемпотентный ответ сохраняются атомарно. Два разных запроса одного старого предложения не создают два задания. Ошибка после создания откатывает всё. До нажатия никаких резервов и задач нет.

## Секреты и транспорт

API-ключ существует только в форме ввода и шифрованном серверном хранилище AES-256-GCM с AAD площадки. Ключ шифрования — WMS_MARKETPLACE_KEY (base64, 32 байта) либо лениво созданный .data/marketplace-secret.key с правами 0600; файл публикуется атомарно. Сохранять его отдельно от дампа БД при резервном копировании. Потеря ключа требует повторного подключения.

Сырые credentials не входят в JSON ответов, SQL commands, события, browser storage и React Query mutation cache. Fingerprint команды подключения — HMAC. Marketplace HTTP-команды обходят складской browser replay registry; сервер сохраняет безопасный ответ в общей commands с собственным fingerprint namespace и проверяет другие реестры requestId. Все операции доступны только руководителю с обычными Origin/CSRF-проверками. Сессия и версия подключения перепроверяются после внешнего ожидания.

Сетевые запросы выполняются вне складской блокировки; лимиты страниц, ответа, времени, pacing и запрет redirect ограничивают загрузку. Ошибки площадки превращаются в фиксированные собственные сообщения. Next proxy и HTTPS gateway допускают до 270 секунд для синхронизации; адаптер ограничен 240 секундами. Внешние адреса нельзя передать из UI.

## Web

FSD: entities/marketplaces и entities/assembly-plan читают; features/marketplace-integration и features/assembly-planning выполняют сценарии; /integrations и /planning только компонуют. Контракт — Nest Swagger → Orval. Ключи не копируются в собственные DTO фронта. Ответы проходят runtime-guard перед рендером; запросы и продолжения защищены auth epoch/scope. Смена роли, поздний ответ или malformed JSON не подменяют текущую сессию.
