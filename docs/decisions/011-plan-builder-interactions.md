# ADR 011. Числовые параметры, поворот и корзина конструктора

Дата: 23 октября 2026. Статус: реализовано для локального этапа 3.

## Формы и альтернативы жестам

Размеры помещения, геометрия прохода/места/секции, стена и отступ входа редактируются численно. Все метрические поля используют step=any: привязка к 0,5 м относится только к перетаскиванию. Можно задать реальный размер 1,2 м или 28,2 м. Ориентация доступна полем 0/90/180/270 и отдельной кнопкой поворота на 90° в карточке. Для входа поворот заменён выбором стены. Физические ограничения адреса в миллиметрах не меняются при повороте плана. Применяется `rule/gesture-has-control-alternative`.

Новые проходы имеют предлагаемые размеры 2 × 3 м. Вход получает первое подходящее свободное положение на стене с учётом других активных входов. Архивные проёмы не занимают стену. Эти предложения помогают начать форму; окончательную проверку выполняет API.

Геометрия одной секции отправляется только через section API. Редактирование ограничений отдельного яруса не отправляет координаты/габариты/поворот секции. У редактирования секции отдельный resolver: он проверяет code/name и геометрию, а не скрытые профили ярусов. Поэтому пустую секцию после удаления последнего яруса можно настроить и дополнить новым ярусом. При создании секции по-прежнему нужен хотя бы один корректный профиль. Для предложения следующего номера учитываются и архивные адреса, код которых нельзя повторно выдать.

## Удаление и восстановление

Удаление убирает объект с плана в постоянную корзину. Не вводится дополнительное подтверждение для этой обратимой операции: `rule/destructive-proportional`. Кнопки называют область действия: «Удалить выбранный адрес с плана», «Удалить секцию и активные ярусы», «Удалить проход с плана», «Удалить вход с плана» — `rule/name-object-scope-consequence`.

Непустой адрес, физический нулевой поддон, удержание возврата и незавершённое перемещение с адресом как источником или целью дают видимую причину рядом с заблокированным действием. Историческое завершённое движение не блокирует удаление. Для секции проверяются все её активные адреса. Подсказки UI не подменяют транзакционную серверную проверку.

Корзина доступна постоянно. Нет временного «отменить», которое исчезало бы до реальной потери возможности восстановления: `rule/undo-only-when-honest`. Восстановление секции возвращает только адреса из archivedLocationIds. Ранее отдельно удалённый ярус показывается отдельно; если секция тоже архивна, его восстановление заблокировано с указанием сначала восстановить секцию. При конфликте геометрии объект остаётся в корзине, ошибка сервера видна, пользователь может освободить место или изменить размеры помещения и повторить.

Существующие ID/QR/история сохраняются, а коды архивных адресов остаются занятыми. Проход и вход не являются адресами хранения и не получают QR/остатки.

## Состояния и архитектура

Формы сбрасываются при открытии или смене редактируемого ID, а не при каждом snapshot polling. Ошибка API оставляет введённые значения и диалог открытыми: `rule/preserve-user-input`, `rule/error-states-recovery`. Pending блокирует отправку и закрытие новых форм; подпись действия остаётся стабильной с aria-busy. В режиме обзора карточки показывают остатки, параметры и QR; запись, поворот и удаление доступны в конструкторе. Отдельно предусмотрены пустая корзина, пустая секция и заблокированное восстановление: `rule/cover-reachable-states`.

Действия используют нативные кнопки и подписанные поля; диалоги сохраняют нативное управление фокусом. Кнопки QR/восстановления называют объект: `rule/accessible-name-required`, `rule/keyboard-complete-flow`.

FSD: Zod-схемы, мапперы, предварительные причины и проекция корзины находятся в feature/lib; API-команды — feature/model/use-location-actions; формы, карточки и корзина — feature/ui. Стили новых панелей — отдельный CSS module. Контракты приходят только из NestJS OpenAPI через Orval; общий пакет контрактов не вводится.

## Проверки

Регрессионные тесты проверяют дробные размеры, четыре поворота и недопустимый угол; отсутствие геометрии в обновлении профиля яруса; редактирование пустой секции и игнорирование скрытого профиля; запрет пустой новой секции; разные адреса новых ярусов без учёта регистра; минимум прохода; пределы проёма по выбранной стене и свободное предложение входа; удаление при физическом нулевом поддоне/возврате/обоих концах движения; честное групповое восстановление корзины.
