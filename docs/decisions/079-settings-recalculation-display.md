# 079. Смена настроек без ложного нулевого плана

Пользователь изменил покрытие с 56+14+7 на 28+0+5 и увидел ноль до публикации сезонного прогноза. Причина: новый compatibilityKey исключает прежнюю presentation; bootstrap из snapshots с cacheCurrent=false сохранял промежуточный базовый расчёт как предыдущий. После CPU worker фактический сезонный план стал 376 коробов сборки и 124 отправки.

При ожидающем текущем прогнозе восстановление display-кэша из fallback запрещено. Совместимый сохранённый расчёт остаётся доступным и неисполняемым. Если совместимого результата нет, сервер возвращает unavailable и объяснение пересчёта; web не показывает числа, даты и действия из промежуточного payload. Настройки и уточнения остаются доступны. Опубликованный план с корректным нулём не скрывается.

Движок, количества, частота импорта, пользовательские настройки и публичный контракт не меняются. Повторное выполнение остаётся в штатном worker с проверкой ключа/lease. Проверки покрывают изменение настроек, отсутствие первого кэша, сохранение предыдущей версии, последующую публикацию и настоящий ноль.
