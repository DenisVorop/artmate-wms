# 061. Линии пути на карте сотрудника

placementRoutePath восстанавливает тот же путь Dijkstra, который использует подбор хранения. У каждого узла есть физические координаты; короткие подходы и дверные рёбра хранят ортогональные изгибы и корректно разворачиваются. Восстановление включено только для одного отображаемого адреса; обычный placementRoutes не создаёт массивов путей для всех кандидатов. Линия упрощается только на совпадающих или коллинеарных точках без потери обратного движения. Длина отрезков совпадает с расстоянием; диагональные срезы через стены/оборудование не допускаются. Дополнительный лимит — 12000 точек; unknown/unreachable не рисуют линию, ярусы одной секции дают нулевое горизонтальное расстояние без выдуманного пути.

Защищённый GET /api/work-route получает ссылку на документ, а не произвольные координаты сотрудника. Проверяет свежую сессию и принадлежность работы; работник не получает маршрут чужого задания. Сервер выбирает оба адреса по полному состоянию: FIFO→общая сборка, приёмка→текущая рекомендация, накопитель→закреплённое хранение, from/to перемещения, следующий короб→однозначный адрес своей отгрузочной зоны. Неоднозначная зона и завершённая работа дают явное unavailable без ложного направления. Запрос не захватывает работу, не сканирует и не меняет склад.

Ответ Swagger/Orval содержит sourceLocationId, targetLocationId, points, status, distanceMeters, note, revision и layoutKey. WorkRouteRequest в entity является alias сгенерированных параметров. LayoutKey — SHA-256 канонической проекции планировки. Одинаковые тестовые векторы подтверждают Node/WebCrypto; изменение порядка строк/названий/revision не меняет ключ, геометрии/архива/блокировки — меняет. Сериализация версионирована work-route-layout-v1; при изменении проекции обе реализации и тестовый вектор меняются вместе. Это проверка соответствия изображения, не замена серверных прав.

entities/warehouse-map только читает GET при открытом диалоге. Query key включает auth scope/epoch, ссылку задания, контекст и каноническую геометрию; сигнал отменяет устаревшую загрузку. Пока карта открыта, read-only данные обновляются раз в 5 секунд. Несовпадающий hash или адрес текущего шага не показывает старый путь. Обычные сканы других сотрудников не сбрасывают неизменившийся маршрут из-за общего revision. Поздний ответ прежней схемы/сессии не переносится в новый контекст.

Сохранён компактный native dialog и возврат фокуса в текущий EmployeeScan. По умолчанию в кадре весь обход и оба места, есть весь склад. Контурная метка «Взять», заполненная «Нести» и стрелка показывают направление. Адреса/ярусы и метры вынесены в короткие подписи. Без подтверждённой геометрии видны адрес/причина, но не прямая под видом маршрута. Печать/учёт/FIFO/назначение/баланс и схема БД не меняются.
