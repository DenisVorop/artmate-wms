# ADR 024 — Безопасная печать этикеток короба

Статус: принято. Дата: 23 октября 2026.

## Решение

Существующий маршрут `/labels/[type]/[id]` остаётся единственным экраном отдельной этикетки адреса, паллеты или короба. Типизированный запрос `getLabel` вынесен в `features/labels/model`; API и Orval остаются источником типов. Новые endpoint, клиентские коды и локальные складские записи не создаются.

Открытый короб запрашивается по текущему `openBoxCode`. После упаковки тот же читаемый код возвращает ту же этикетку готового короба. QR payload, код и название отображаются из ответа сервера. Печать и повторная печать выполняют только чтение и не подтверждают короб, скан товара или упаковку.

SVG отображается через `img` с закодированным data URI; HTML из ответа не вставляется в DOM. Кнопка печати доступна после успешной загрузки изображения именно текущего ответа. Смена этикетки и повтор загрузки имеют собственную идентичность готовности, поэтому старое событие загрузки не разрешает печатать новый QR. Ошибки запроса и изображения имеют отдельные действия повтора; для коробов всегда доступен возврат к сборке.

На экране сохраняются графитовые стеклянные панели, на бумаге — контрастная чёрно-белая этикетка. CSS module задаёт лист 100 × 70 мм без полей, такой же размер самого макета и скрывает действия. Отступ экрана находится внутри feature и снимается при печати; общий page wrapper не добавляет отступ к листу. Общий print reset приложения используется без изменений. На узких экранах сам физический размер макета сохраняется с горизонтальной прокруткой превью.

## Проверка и границы

TypeScript и архитектурная проверка подтверждают типизированный запрос и границы FSD. Браузерная проверка входит в общий сценарий сборки: открытый короб → этикетка → скан короба → закрытие → повторный GET по тому же коду. Новые тесты, повторяющие прямую разметку, не добавляются. Наличие физического принтера и фактическое качество печати не проверялись; пользователь выбирает размер бумаги 100 × 70 мм в диалоге печати.
