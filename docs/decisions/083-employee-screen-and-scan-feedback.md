# ADR083 — экран и звуковая обратная связь сотрудника

Дата: 28 октября 2026.

## Решение

Рабочий экран /work удерживается включённым, пока собственная смена имеет статус working и документ видим. На перерыве, выходе, смене аккаунта или закрытии страницы ресурсы освобождаются. После возврата из фона удержание запрашивается заново. Поздний ответ старого запроса освобождает свой sentinel и не заменяет новую сессию. Отказ/системное освобождение показываются явно; бесконечного цикла повторных запросов нет.

Один AudioContext принадлежит рабочему экрану и активируется непосредственно касанием/клавишей. Кнопка «Включить звук сканов» и проверка звука в меню позволяют явно проверить громкость. После аудиопрерывания снова доступна активация. Никаких сетевых аудиофайлов, фонового воспроизведения или обхода ограничений iOS.

Shared EmployeeScan озвучивает результат onScan, а не помещение кода в очередь. Для серверной команды сигнал следует после её ответа; локально проверенный первый код пары подтверждает только текущий шаг, не изменение остатков. Gateway pass не звучит и остаётся синхронным; handled/blocked звучат после результата перехватчика. Ошибка валидации, отклонённый код или сбой команды дают сигнал ошибки. Очередь сохраняет прежнее поведение остановки и восстановления. Камера/ручной ввод/HID используют один путь. Завершивший короб скан может успешно сменить форму до возврата ответа — это не причина терять подтверждающий звук. Ответы прежнего auth epoch молчат.

Успех: два коротких высоких тона. Ошибка: три низких тона. Новый результат прекращает предыдущие тона, чтобы не накапливать устаревшие звуки при серии сканов. Сигнал ошибки имеет приоритет до завершения своих трёх тонов: подтверждение последнего скана не заглушает предупреждение о сброшенном хвосте очереди. Звуки не являются заменой экранной ошибки; физический писк сканера означает только чтение кода. Ошибка браузерного аудио не влияет на складскую команду.

## Границы

Механика устройства — shared/lib и shared/ui; виджет задаёт только active/sessionKey из текущего пользователя и смены. API и складской учёт не меняются. Удержание требует защищённого контекста и поддержки браузера. Энергосбережение, ручная блокировка, переключение приложения и системные аудионастройки остаются под контролем телефона. Нельзя обещать сканирование заблокированным телефоном или слышимость на любом устройстве без физической проверки.

Источники: [Screen Wake Lock](https://www.w3.org/TR/screen-wake-lock/), [WebKit: Safari 18.4 и Home Screen Web Apps](https://webkit.org/blog/16574/webkit-features-in-safari-18-4/).
