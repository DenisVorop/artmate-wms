# 052 — Перехват QR рабочей зоны и отгрузка сотрудником

Дата: 2026-10-24. Статус: принято.

## Скан зоны до бизнес-команды

QR рабочей зоны обрабатывается до очереди кодов товара/коробов/адресов. Shared EmployeeScanGateway — обобщённый перехватчик, без знания склада и формата QR. Его владелец в widget задаёт `canIntercept(value)` и `intercept(value)`. Формат рабочей зоны и команды начала/выхода принадлежат feature/model и серверу.

Синхронный `canIntercept` нужен для обычных товарных кодов: они немедленно возвращают pass и попадают в существующую последовательную очередь. Даже короткий Promise для каждого скана создал бы окно блокировки и мог потерять быстрый ввод; тест проверяет шесть одинаковых сканов подряд без дедупликации. Только код, требующий перехвата, может запустить асинхронное действие. Пока оно выполняется, общий синхронный lock блокирует остальные коды, включая обычные бизнес-коды, и все поля EmployeeScan показывают состояние обработки.

Результаты: pass передаёт код бизнес-очереди; handled завершает обработку без бизнес-скана; blocked сохраняет поле и очередь. Если в очереди был непринятый код, он восстанавливается в поле. Иначе оставленный заблокированный код выделяется целиком, чтобы следующий HID-ввод заменил его, а не приклеился к нему. Ошибка перехватчика сохраняет ввод и снимает lock. Асинхронный ответ прежнего контекста/auth epoch не меняет поле нового действия.

Widget проверяет незавершённую работу, переносимый груз, dirty-ввод и текущие сканы; отдельный root zoneBusy защищает навигацию и смену. Gateway не добавляет себя в business scan.pending, иначе обработчик зоны блокировал бы собственную команду. Серверный startZoneWork атомарно выбирает или возобновляет работу и сохраняет warehouse.zoneWork. В браузере нет effect с автоматическим claim/pack/place.

Это маршрутизация полного кода через существующие поля EmployeeScan, без глобальной подмены DOM/клавиш. Работа аппаратного сканера не заявляется проверенной без устройства. Существующие ручные формы и их dirty-guards сохраняются (`rule/preserve-user-input`, `rule/cover-reachable-states`).

## Восстановление остановленной очереди

Только после завершившегося неуспешного скана доступно раскрываемое действие «Отменить непринятые сканы». Оно показывает точное число непринятых кодов и требует именованного нажатия «Отменить N сканов». Локальная очередь очищает ошибочный код и его неотправленных последователей; API-запросы не отменяются, принятые сервером факты сохраняются. Пользователь получает явное указание проверить товар без подтверждения. Автоматической очистки нет.

Отмена недоступна во время запроса и не удаляет техническую запись replay. Она доступна даже после внешнего отключения текущего шага. Завершившийся запрос такого шага публикует локальное settled-состояние: принятый скан удаляется, оставшиеся коды останавливаются для явного разбора. Это снимает тупик навигации без переноса кодов в новую работу (`rule/cover-reachable-states`, `rule/preserve-user-input`).

## Отгрузка по назначению

EmployeeShipping читает только свою warehouse.zoneWork: jobKind=shipping, точный jobId и связанную активную shipping-зону. Из общего списка draft-отгрузок задание не выбирается, чужое назначение не подхватывается. Планирование FIFO, выбор состава и предварительные перемещения остаются у руководителя.

Сотрудник видит один следующий неподтверждённый короб из shipment.boxIds, его фактический адрес и код. Скан — реальный, без подстановки ожидаемого кода; API может принять любой входящий в точный зарезервированный набор короб. Прогресс строится только из уникальных серверных scannedBoxIds, принадлежащих этому набору. Скан сам не списывает остаток. Статус, собственность, working-смена, актуальные адреса и физические перемещения повторно проверяются сервером.

После подтверждения всех коробов показаны точные коды, фактическое количество раскрасок и число коробов. Остаток меняет только именованное действие «Отгрузить N коробов» (`rule/name-object-scope-consequence`, `rule/irreversible-action-safeguard`, `rule/one-primary-action`). Оно недоступно при ожидающих сканах, текущем перехвате зоны, недоступном составе или незавершённой команде. Нельзя отгрузить пустой или неполный набор.

finishShipmentWork получает canonical QR назначенной зоны как контекст серверного назначения, сформированного после реального startZoneWork. Интерфейс не объявляет это повторным физическим сканированием зоны. Автоматического finish нет. После успешной команды backend сам выбирает следующее задание этой зоны; UI отображает новый committed assignment. Если работы нет, показывается серверная причина и путь к выбору зоны.

## Архитектура и проверка

Типы WorkZoneDto/ZoneWorkDto/ShipmentDto и команды получены через Orval. Feature использует useSession и useWarehouseCommands с существующими actor/replay/auth-epoch проверками. UI, интерпретация состояния и команды разделены по FSD. Другие employee-features и widget не импортируются; root компонует их через публичный export.

Scoped tests проверяют собственность/точное назначение, уникальные фактические сканы и текущий неподтверждённый короб, неполный/пустой/дублирующийся состав, повторную недоступность коробов после сканов, быстрый бизнес-ввод, общий gate во время zone-start и сохранность непринятой бизнес-очереди при сбое перехватчика. Браузерные сценарии всей рабочей зоны проверяются root при интеграции.
