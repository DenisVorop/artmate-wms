# ADR 056 — локальный HTTPS-доступ сотрудников с телефона

Статус: принято.

## Контекст

Сотрудник открывает компактный `/work` на телефоне в складском Wi-Fi. Приложению нужен доверенный secure context, а существующий управленческий localhost HTTP должен продолжить работать. Публикация в интернет не запрошена. Прямой доступ к PostgreSQL и Nest API из сети не нужен.

## Решение

Оставляем Next и Nest на `127.0.0.1:3080/4080`. В составе стартового процесса добавляем небольшой Node HTTPS reverse proxy на приватных IPv4, порт 3443. Из поиска адресов исключаем известные VPN и виртуальные интерфейсы (utun/tun/tap, awdl/llw, WireGuard/Tailscale, Docker/bridge и VM-адаптеры), чтобы не предлагать сотруднику недоступный адрес туннеля. Неизвестные имена физических интерфейсов сохраняем. `/api` проксируется напрямую в Nest, остальные запросы — в Next. Для первого подключения статичная HTTP-страница на 3442 раздаёт только инструкцию и публичный CA-сертификат; пароли, API и данные склада по этому HTTP не передаются.

`yarn phone:setup` создаёт отдельную локальную CA и IP SAN leaf-сертификат через OpenSSL, в исключённом из Git каталоге `.data/phone-access` с закрытыми правами. Системное доверие автоматически не меняем; владелец один раз устанавливает CA на рабочий телефон и проверяет отпечаток. CA — общий доверенный издатель, её ключ защищается на компьютере склада. Leaf действует 365 дней и обновляется с сохранением CA при смене приватных IP/приближении срока. `yarn start` автоматически использует готовую конфигурацию и обновляет leaf при необходимости.

API получает конкретные LAN HTTPS origins через `WEB_ORIGIN`. Cookie получают `Secure` на HTTPS-границе; localhost HTTP сохраняется. Не добавляем `trust proxy` или зависящий от клиентского заголовка режим TLS. Gateway удаляет forwarded-заголовки и не меняет Origin/CSRF. Host проверяется по точному списку приватных адресов, upstream фиксирован на loopback. HTTP provisioning не является файловым сервером.

Gateway закрывается вместе со стартовым процессом; ошибка его подготовки/слушателя не останавливает localhost. Нет туннеля, внешней публикации, установки глобальной CA, сервис-воркера или обещания offline.

## Проверка и последствия

Node tests проверяют private NIC/Host, запросы/заголовки, отсутствие доступа к ключам через provisioning HTTP, Secure-cookie, X509 SAN/цепочку/срок и повторную генерацию. Интеграционный TLS-тест использует временные loopback fixtures без БД; закрывает соединения после проверки.

Телефон должен доверять локальной CA, иметь сетевой доступ к компьютеру и использовать HTTPS URL. Для постоянной работы полезно закрепить IP компьютера и отключить сон во время смены. Аппаратная проверка конкретного телефона/сканера выполняется отдельно. Полная инструкция: [PHONE_ACCESS.md](../PHONE_ACCESS.md).
